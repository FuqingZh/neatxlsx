# neatxlsx M0/M1 Report Trust Design Proposal

Version: v1.0
Date: 2026-08-11
Status: M0 and M1 implemented locally; release publication pending

## Decision summary

M0 and M1 establish the trust boundary on which the later report experience is
built:

- **M0** adds reproducible reference-report sources, compact structural
  manifests, independent readers, and a manual visual rubric. Generated XLSX
  files are evidence, not committed binary contracts.
- **M1** gives every admitted Polars dtype an explicit Excel storage and display
  policy. Values that Excel cannot represent without loss are written as exact
  literal text, with one deterministic warning per affected logical column.
- Unsupported nested or opaque dtypes fail schema preflight before the affected
  logical sheet mutates the native workbook.
- Python owns dtype classification, preflight, and lazy Polars normalization.
  Rust owns cell conversion, XLSX storage, format planning, warnings, and
  rendering.
- The one-pass and two-pass writer paths use the same Arrow value converter.
- Format precedence becomes deterministic, and invalid `Format` values fail at
  Python construction time rather than being silently ignored.
- M0/M1 add no public names and no new `Workbook` or `write_sheet()`
  parameters. M1 does intentionally correct observable cell kinds, values,
  formats, warnings, and validation behavior.

This proposal selects the implementation semantics. The companion
[implementation plan](../implementation-plan/20260811-v1.0-neatxlsx-m0-m1-report-trust-implementation-plan.md)
defines the delivery slices and gates.

## Context

The current writer already provides the important lifecycle and scale
properties: Polars DataFrame and LazyFrame input, Arrow C streams, repeated
sheet writes, automatic physical-sheet splitting, literal strings,
constant-memory Rust worksheets, ZIP64, and transactional replacement.

The remaining M1 problem is semantic. The current native converter has only
blank, string, and `f64` number cells. Primitive integers are cast to
`f64`; booleans are strings; and several other Arrow dtypes fall back to an
Arrow dtype description. The body-autofit path also converts through Polars
`AnyValue`, while the ordinary path converts Arrow arrays directly, so the
same source dtype has two conversion implementations.

Observed current examples include:

| Polars value | Current stored result | Problem |
| --- | --- | --- |
| `True` | text `"True"` | Loses native boolean kind |
| `Int64(9223372036854775807)` | numeric `9223372036854776000` | Silent precision loss |
| `UInt64(18446744073709551615)` | numeric `18446744073709552000` | Silent precision loss |
| `Date` | text `"Date32"` | Dtype description replaces value |
| `Datetime` | text such as `"Timestamp(Millisecond, None)"` | Dtype description replaces value |
| `Decimal` | text such as `"Decimal(38, 2)"` | Dtype description replaces value |
| `Categorical` or `Enum` | Arrow dictionary description | Label is lost |
| nested or binary value | Arrow dtype description | Neither a value nor an explicit rejection |

Excel stores only 15 significant numeric digits. Therefore a correct writer
cannot preserve every Polars integer or decimal as an Excel numeric cell. The
design favors exact values over uniform numeric cell kinds.

The current format pipeline also merges a body base patch after role formats.
That patch clears all borders, including explicit user border overrides. Invalid
alignment and border values can be silently ignored or mapped to no border.

## Goals

1. Make stored values, cell kinds, displayed formats, precision, temporal
   units, and timezone behavior explicit and testable.
2. Preserve exact source meaning without requiring a second data materialization.
3. Keep ordinary small integers, decimals, and supported temporal values as
   natural Excel cells.
4. Surface unavoidable text fallback without turning safe fallback into a
   write failure.
5. Reject unsupported schemas early and leave an open workbook usable.
6. Ensure all autofit modes write identical value semantics.
7. Make format validation and precedence predictable.
8. Establish reference artifacts that can guide M2 visual work without making
   binary files or screenshots compatibility contracts.

## Non-goals

- New report-style, theme, column-rule, or worksheet-view APIs.
- Generic serialization for lists, structs, arrays, binary, or Python objects.
- Formula inference or formula authoring.
- Reading or modifying arbitrary existing workbooks.
- openpyxl interoperability; that remains M3.
- A pandas, Arrow, or CSS styling compatibility layer.
- A new DataFrame engine or a separate XLSX backend.
- Performance claims beyond regression protection.

## Preserved invariants

- All source and fallback strings use literal string writes.
- Logical tables still split at Excel row and column limits.
- `SheetReport` continues to map one logical write to all physical sheets.
- `Autofit(mode="none")` and `Autofit(mode="header")` consume one data
  source; body-aware modes may consume two sources but must normalize both
  identically.
- The ordinary path remains streaming and batch-bounded.
- ZIP64 and transactional replacement behavior do not change.
- A failed logical write does not append a successful report.
- Python 3.11+, abi3-py311, and supported Polars lanes remain package gates.

## M0 reference-report design

### Repository layout

```text
tests/reference_cases.py
tests/fixtures/report-reference/*.json
tests/integration/test_report_reference.py
scripts/generate_report_reference.py
dist/report-reference/                 # ignored generated evidence
```

`tests/reference_cases.py` owns deterministic input factories. The generator
uses those factories and the public API; tests do not rely on a second private
workbook construction path.

### Scenario set

| ID | Purpose | Default CI artifact |
| --- | --- | --- |
| `ordinary-scientific` | identifiers, counts, decimals, missing values, significance-like values | XLSX and manifest |
| `mixed-dtype` | all M1 dtype, precision, temporal, and literal-text decisions | XLSX and manifest |
| `multi-level-header` | header hierarchy, horizontal merges, freeze offsets | XLSX and manifest |
| `multi-sheet-pipeline` | repeated and looped `write_sheet()`, report ordering, lifecycle | XLSX and manifest |
| `split-planning` | synthetic row/column limit planning and physical offsets | compact planner manifest |

The generator offers `--include-large` for an end-to-end workbook that
crosses a real Excel limit. This expensive artifact is release evidence, not a
default pull-request job. Default CI validates the same split arithmetic with
synthetic dimensions in the Rust planner.

### Manifest contract

Each expected JSON file contains only stable, reviewable observations:

- manifest schema version and scenario ID;
- requested logical sheets and ordered `SheetReport` data;
- physical worksheet names, dimensions, freezes, merges, and selected column
  widths;
- sentinel cells with address, canonical kind, canonical value, and number
  format;
- literal-string assertions for formula-looking text; and
- an optional `known_gaps` list reserved for intentionally deferred behavior.

Canonical cell kinds are `blank`, `string`, `number`, `boolean`, and
`error`. Temporal cells are numbers plus number formats; the manifest also
records the reader-observed logical value where useful.

The current M1 mixed-dtype manifest has no stale dtype gaps: admitted behavior
is asserted by ordinary sentinels. If a future scenario uses `known_gaps`, it
must describe deferred behavior and never bless a lossy value as a contract.

Generated XLSX bytes, ZIP member order, compression ratios, timestamps, and
whole-file hashes are not contracts.

### Oracles

The test uses three independent surfaces:

1. openpyxl observes cell values, kinds, number formats, freezes, merges, and
   dimensions.
2. ZIP and OOXML assertions observe relationships, worksheet parts, cell type
   attributes, merge declarations, and literal strings.
3. `SheetReport` and the compact manifest observe logical-to-physical report
   structure and warnings.

The generator writes an actual manifest under `dist/report-reference/` and
compares it with the expected fixture. Fixture replacement requires an explicit
`--accept` flag so normal generation cannot silently bless output changes.

### Visual rubric

The manual rubric records pass, concern, or not-applicable for:

- header hierarchy and merged-header clarity;
- text, boolean, integer, decimal, and temporal alignment;
- readable numeric precision and scientific notation;
- missing-value visibility;
- width, wrapping, density, and obvious truncation;
- consistency across sheets and split parts; and
- formula-looking text remaining visibly literal.

Excel and LibreOffice observations may be attached to a release, but
screenshots are not a pull-request gate.

## M1 dtype contract

### Selected mapping

| Polars dtype | Excel storage | Default display | Lossless fallback and warning |
| --- | --- | --- | --- |
| `Null` or null cell | blank, or configured missing token | existing missing policy | none |
| `Boolean` | native boolean | Excel boolean | none |
| signed/unsigned integers, including `Int128` | number when the cell has at most 15 significant decimal digits | `0` | exact decimal text for 16+ digits; `precision-as-text` |
| `Float32`, `Float64` | number | existing decimal/scientific policy | NaN and infinities retain the existing blank-or-token policy |
| `Decimal` | number when unscaled significant digits and scale are both at most 15 | `0` or fixed scale `0.00...` | exact fixed-point text at dtype scale; `precision-as-text` |
| `String` | literal text | text | none |
| `Categorical`, `Enum` | literal label text after lazy Polars cast | text | none |
| `Date` | Excel date number for 1900-01-01 through 9999-12-31 | `yyyy-mm-dd` | ISO date text outside range; `temporal-as-text` |
| timezone-naive `Datetime` | Excel datetime number when in range, millisecond-aligned, and millisecond round-trip safe | `yyyy-mm-dd hh:mm:ss.000` | ISO text at source-unit precision; `temporal-as-text` |
| timezone-aware `Datetime` | ISO 8601 literal text with numeric UTC offset and source-unit precision | text | this is the normal mapping; no warning |
| `Time` | Excel time number when millisecond-aligned and round-trip safe | `hh:mm:ss.000` | ISO time text at source-unit precision; `temporal-as-text` |
| `Duration` | Excel day fraction when nonnegative, millisecond-aligned, and round-trip safe | `[h]:mm:ss.000` | exact signed integer plus unit, such as `-1000us`; `temporal-as-text` |
| `Binary`, `List`, `Array`, `Struct`, `Object`, unknown nested/opaque dtype | not admitted | none | schema-preflight `TypeError` |

“Significant decimal digits” excludes a sign and leading zeros. Zero has one
digit. The conservative 15-digit rule is intentional even where a particular
larger integer might happen to be representable by binary floating point.

A mixed integer column may therefore contain numeric cells for ordinary values
and literal text cells for precise identifiers. This keeps common reports
natural without silently changing large values. The report warning makes the
mixed representation auditable.

For Decimal values, fixed-point fallback never switches to scientific notation
and retains trailing zeros implied by the dtype scale.

### Temporal details

- Millisecond alignment means the source value has no remainder below one
  millisecond.
- Round-trip safety means converting to an Excel day fraction and back to the
  original integer milliseconds returns the same value.
- Date and naive datetime ranges begin at 1900-01-01. Earlier values use text
  rather than relying on workbook date-system edge behavior.
- Sub-millisecond values use text because common XLSX readers expose only
  millisecond precision even when the underlying serial can carry more.
- Negative durations use text because the default Excel date system does not
  reliably display negative time values.
- Timezone-aware values are normalized lazily by Polars into ISO 8601 text.
  The numeric offset preserves the instant boundary; no timezone is silently
  stripped or converted to a naive Excel datetime.

### Unsupported schema error

Schema validation runs after column selection is known and before requesting
the first Arrow batch for the logical write. The message has this shape:

```text
Unsupported Polars dtype for column 'payload': Struct(...).
Convert the column to String explicitly before write_sheet().
```

The error is `TypeError`. Earlier successfully written sheets and the open
workbook remain usable; the rejected logical sheet produces no report entry and
does not poison later writes.

## Ownership and data flow

```text
DataFrame/LazyFrame
  -> collect schema
  -> Python dtype preflight and ordered column plans
  -> lazy normalization for Categorical, Enum, and timezone-aware Datetime
  -> Arrow C stream(s)
  -> PyO3 bridge v3 with ordered column plans
  -> one Rust Arrow cell converter for sizing and writing
  -> cell kind + exact value + optional warning code
  -> format planner
  -> rust_xlsxwriter
  -> SheetReport warnings and transactional close
```

### Python policy layer

Add a private `python/neatxlsx/_dtype.py` module. Its principal result is an
ordered private `_ColumnValuePlan` with:

- source column name and zero-based logical index;
- normalized value kind;
- decimal precision and scale when applicable;
- temporal unit and timezone when applicable; and
- inferred number-format patch.

The planner returns the normalized LazyFrame plus plans in source-column order.
Categorical and Enum columns are lazily cast to String. Timezone-aware datetime
columns are lazily formatted to the selected ISO representation. No Python
rows are materialized.

The planner is private. It is not exported from `neatxlsx.__init__`.

### Bridge layer

The additional ordered metadata changes the private bridge contract:

- ABI `2` becomes `3`;
- contract `neatxlsx.xlsx.writer.v2` becomes
  `neatxlsx.xlsx.writer.v3`;
- transport remains `arrow_c_data`; and
- Python and native package smoke tests must reject a mixed v2/v3 install.

The bridge translates private Python plans to Rust structs. It does not
classify Polars dtypes or choose fallback policy.

### Rust mechanics layer

The internal `CellValue` becomes:

```text
Blank | String(String) | Number(f64) | Boolean(bool)
```

Dates, datetimes, times, and durations use numeric values plus number formats;
they do not require public cell objects.

The converter accepts an Arrow array, row index, and immutable column plan and
returns the cell value plus an optional warning code. It uses existing
polars-arrow temporal helpers and rust_xlsxwriter date/time conversion support;
it does not round-trip body values through Python objects.

Both the write pass and body-autofit scan call this converter. The two-pass path
may still request two Arrow streams, but it no longer uses a separate
`AnyValue` body conversion. `AnyValue` remains acceptable for the small
custom-header DataFrame path.

Warnings are deduplicated in the logical-sheet planner by
`(source_column_index, warning_code)`, then emitted in source-column order.
Physical sheet splitting does not duplicate them.

## Warning contract

M1 uses two stable machine-readable prefixes:

- `[precision-as-text]`
- `[temporal-as-text]`

Example:

```text
[precision-as-text] column 'sample_id' contains values beyond Excel's
15-digit numeric precision; affected cells were written as exact text.
```

Each prefix appears at most once per affected logical column in one
`SheetReport`. No warning is emitted when a column does not encounter a
fallback cell. Prefixes and ordering are contract tested; explanatory wording
may be improved without changing the code prefix.

## Format design

### Validation

`Format.__post_init__()` validates every non-`None` field:

- `bold`, `italic`, and `text_wrap` must be exact booleans;
- `font_size` must be an integer from 1 through 409, excluding booleans;
- `align` accepts `general`, `left`, `center`, `right`, `fill`,
  `justify`, `center_across`, or `distributed`;
- `valign` accepts `top`, `bottom`, `vcenter`,
  `vertical_center`, `vjustify`, `vertical_justify`,
  `vdistributed`, or `vertical_distributed`;
- `border`, `top`, `bottom`, `left`, and `right` must be integers
  from 0 through 13, excluding booleans;
- `font_name` and `num_format` must be nonempty strings; and
- colors must be six hexadecimal RGB digits with an optional leading `#`;
  the normalized bridge value is uppercase `#RRGGBB`.

Wrong Python value types raise `TypeError`; out-of-domain values raise
`ValueError`. `Format.replace()` receives the same validation through
dataclass reconstruction.

### Defaults and precedence

Body and header defaults are represented directly:

- body text, integer, decimal, and scientific roles default to no border;
- header defaults retain their border; and
- the late `base_format_patch` that clears border fields is removed.

For M1, the effective order is:

```text
report role default
< inferred dtype number-format patch
< explicit Workbook role override
< scientific conditional overlay
```

Only non-`None` fields overwrite earlier layers. Consequently a
`decimal_format=Format(font_color=...)` retains the inferred decimal scale,
while an explicit `num_format` replaces it. Explicit user border fields are
never cleared later.

Future M2 sheet or column rules may be inserted between Workbook role override
and conditional overlays, but M1 does not expose such a rule.

The private format plan carries default role patches and explicit user patches
separately across the v3 bridge. The existing internal per-column override hook
holds inferred dtype formats and is propagated to every physical split sheet.

## Compatibility and release policy

M0 changes tests and documentation only.

M1 has no new public names but intentionally changes observable behavior:

- booleans become native boolean cells;
- large integers and decimals may become exact text with warnings;
- supported temporal values become Excel numeric cells with formats;
- categorical and enum values become labels;
- unsupported dtypes fail before writing instead of producing dtype text;
- invalid formats fail early; and
- user border overrides begin to work consistently.

The architecture, public API contract, type declarations, tests, examples, and
release notes must land with activation. The first release containing complete
M1 semantics should be a pre-1.0 minor release, targeted as `0.2.0`, rather
than an undocumented patch-output change.

## Alternatives considered

### Write every integer and decimal as text

Rejected. It is safe but degrades normal numeric filtering, formulas, sorting,
and report appearance for the common case.

### Always write integer dtypes as numbers

Rejected. Excel's numeric precision makes silent corruption unavoidable for
valid Int64, UInt64, Int128, and Decimal values.

### Reject every value outside Excel's numeric precision

Rejected as the default. Exact literal text preserves the report and is
auditable. Rejection is reserved for types without a selected serialization.

### Pre-scan each column and choose one kind for the whole column

Rejected. It adds another source pass or materialization and weakens the
ordinary streaming path. Per-cell safe fallback plus one column warning is the
bounded-memory choice.

### Convert all difficult values to strings in Python

Rejected. Polars is used where its lazy vectorized semantics are already the
right abstraction—Categorical, Enum, and timezone formatting—but Rust retains
numeric and temporal conversion so accepted values can remain native Excel
cells without Python-row materialization.

### Add a generic nested-value serializer

Rejected for M1. JSON, repr, and delimiter choices are application policy and
can hide type mistakes. Users can explicitly cast to String before writing.

### Keep the AnyValue and Arrow converters in parallel

Rejected. Separate value implementations make autofit mode an accidental
semantic switch.

### Snapshot entire XLSX binaries or screenshots

Rejected. Container metadata and rendering differ across versions and readers.
Compact structural assertions plus deliberate visual review give useful,
reviewable evidence.

## Acceptance criteria

- All M0 scenarios regenerate from deterministic sources.
- Default CI compares compact manifests without committing XLSX binaries.
- No M0 fixture treats a known incorrect dtype description as a contract.
- Every admitted dtype has cell-kind, stored-value, format, precision, unit,
  timezone, and fallback tests for DataFrame and LazyFrame input.
- No reference cell contains an Arrow or Polars dtype description in place of
  its value.
- Large integers and decimals round-trip exactly either as safe numbers or
  literal text.
- Unsupported schemas raise `TypeError` before the affected backend write and
  do not prevent a later valid sheet write.
- All autofit modes produce the same stored cells and warnings.
- Warnings remain logical-column scoped across physical splits.
- Explicit user format fields win at their documented layer.
- Literal-string, ZIP64, splitting, transaction, and package bridge tests
  continue to pass.

## Rollback

M0 assets are independent and can remain if an M1 slice is reverted.

M1 implementation slices must keep Python and Rust bridge versions paired.
Before the `0.2.0` release, an incomplete value-kind activation can be
reverted to the prior converter without changing the public signatures. After
release, the documented exact-value and warning behavior is a compatibility
contract; regressions are fixed forward rather than restored to silent loss.
