# neatxlsx Public API Contract

Version: v1.5
Date: 2026-09-01
Status: current

## Surface

The v0.2 top-level API is:

- `Workbook`
- `Format`, `Autofit`, `ScientificNotation`
- `SheetReport`, `WorksheetPart`
- `Error`, `StateError`, `WriteError`, `CommitError`

There is no top-level write shortcut and no compatibility alias for the
extracted `XlsxWriter` API.

## Workbook

`Workbook(path, ...)` accepts only `str | os.PathLike` local or mounted
filesystem targets. The parent must exist and a symbolic-link target is
rejected. ZIP64, numeric inference, and integer inference default to enabled;
missing-value retention defaults to disabled.

`write_sheet(data, sheet_name, ...)` accepts Polars `DataFrame | LazyFrame`.
Custom headers are Polars DataFrames. Column selections accept one name/index,
an ordered `Sequence`, or a Polars selector. Bool, empty sequences,
set/frozenset, mappings, and generators are rejected. Explicit selections
override inferred roles on those columns while inference continues elsewhere.
Per-call `infer_* = None` inherits the workbook setting.

`header_row_formats` is an optional ordered sequence with exactly one entry per
custom header row. Each entry is a `Format` patch or `None`; `None` inherits
the existing workbook `header_format`. Supplying it without a custom header,
using the wrong length, or including another value type fails before native
backend entry.

`header_column_formats` is an optional mapping from one logical data-column
name or zero-based index to a `Format` patch. Name and index resolution and
validation are identical to `column_formats`: booleans, unknown names,
out-of-range indices, non-`Format` values, and duplicate name/index selections
fail before native backend entry. The patch applies to the generated header and
every row of a custom header. Effective header formatting is merged in this
order:

```text
Workbook.header_format
< header_row_formats[row]
< header_column_formats[column]
```

Header-column patches do not affect body cells. A nonempty
`header_column_formats` mapping with `merge_header=True` is rejected during
Python preflight and leaves the workbook usable; merged ranges do not silently
adopt an anchor-column style. An empty mapping retains existing merged-header
behavior.

`column_formats` is an optional mapping from one column name or zero-based
index to a `Format` patch for body cells. It deliberately does not accept
selectors or multi-column keys. A name and index that resolve to the same
column are a duplicate rule and fail validation. Effective body formatting is
merged in this order:

```text
default report role
< inferred dtype role
< explicit Workbook role format
< column_formats rule
```

Header-row, header-column, and body-column patches propagate to every physical
worksheet part created by row or column splitting. Column-keyed patches are
rebased to each physical column part, while repeated headers on row parts retain
the same logical-column patch. Existing calls that omit these additive
keyword-only arguments retain their prior behavior.

Strings are always literal, including values beginning with `=`, `+`, `-`, or
`@`; neatxlsx never turns input strings into formulas.

Admitted Polars dtypes have explicit storage semantics. Booleans are native
boolean cells; ordinary integers and decimals remain numbers while values that
exceed Excel's safe precision are exact literal text; safe dates, naive
datetimes, times, and nonnegative millisecond-aligned durations are Excel
serials with inferred display formats. Timezone-aware datetimes are literal ISO
text so the offset is not silently discarded. Categorical and Enum columns are
lazily normalized to label text. Binary, List, Array, Struct, Object, and
unknown opaque dtypes fail schema preflight with `TypeError` before the native
writer is entered; the workbook remains usable for later writes.

`SheetReport.warnings` contains deterministic, source-ordered warning strings
with `[precision-as-text]` or `[temporal-as-text]` prefixes, at most once per
affected logical column. `Format` validates types and supported domains at
construction time and normalizes RGB colors to uppercase `#RRGGBB`.

## Lifecycle

- normal context exit calls `close`;
- exceptional context exit calls `abort` and propagates the exception;
- repeated `close` after success and repeated `abort` after abort are
  idempotent;
- closed workbooks cannot abort or write;
- aborted workbooks cannot close or write;
- destruction never commits and emits `ResourceWarning` for unfinished work.

Generation failure raises `WriteError` and aborts. Input type/value mistakes
raise built-in `TypeError` or `ValueError`. Replacement failure raises
retryable `CommitError` with `target`; the caller may retry `close` or abort.

## Reports

`report()` returns `tuple[SheetReport, ...]`, one per successful logical write.
`requested_name` is the caller's value. `worksheets` contains physical parts
after sanitization, uniqueness handling, and Excel-limit splitting. Part row
and column intervals are left-closed and right-open source-table offsets.

## Compatibility and support

The 0.2.1 candidate retains public call signatures and introduces the canonical
single-stream ABI v6 implementation with display-aware column-width estimation.
Concrete column widths can change; published state is tracked by release records.

Version `0.2.0` carries the complete M1 value semantics and the additive
`header_row_formats`, `header_column_formats`, and `column_formats` controls.
Calls written for `0.1.0` retain their signatures and defaults when the new
keyword-only arguments are omitted. The API may still change before 1.0, but
changes remain intentional, documented, and test-backed. Python 3.11+ is
supported with abi3-py311 wheels. The next minor release after Python 3.11
reaches end of life may raise the floor. Free-threaded CPython isn't a v0.2
compatibility promise.

The runtime dependency is `polars>=1.38.1` without an upper bound. The private
Python/PyO3 bridge carrying format plans is paired at ABI/contract v6 and
exposes one single-stream batch writer.
`collect_batches` use is isolated in `neatxlsx._polars`; minimum and latest
stable Polars are mandatory CI lanes, while prerelease smoke is advisory.
