# neatxlsx Architecture

Version: v1.3
Date: 2026-08-31
Status: current

## Purpose and boundary

neatxlsx owns the stable path from a Polars table to an XLSX report table. It
is not an editor for existing workbooks, a generic report engine, or a remote
object-store client.

## Components

- `python/neatxlsx` owns public names, defaults, validation, Polars selectors,
  dtype admission and lazy normalization, LazyFrame batching, lifecycle, and
  transactional commit.
- `crates/neatxlsx_py` is a PyO3 bridge. It validates the paired private
  ABI/contract v6 and transports Arrow C Data streams without product policy.
- `crates/neatxlsx_core` owns worksheet planning, Excel-limit splitting,
  formatting mechanics, value conversion, OOXML generation, and ZIP64.

The extension is private as `neatxlsx._native`. PyArrow is not required:
Polars batches cross the boundary through the Arrow C Stream interface.

## Write data flow

1. Python validates the target, creates a same-directory temporary output, and
   configures the Rust workbook.
2. `write_sheet` normalizes selectors and the distinct header-row,
   header-column, and body-column format patches against the LazyFrame schema,
   rejects unsupported dtypes before native entry, lazily normalizes
   categorical/Enum labels and timezone-aware datetimes, and resolves
   integer/decimal roles.
3. Every autofit mode creates and consumes one
   `collect_batches(chunk_size=...)` source.
4. Rust applies one Arrow value converter for sizing and writing, preserving
   native booleans, exact precision fallbacks, temporal serial formats, and
   literal strings while tracking sampled widths and splitting tables at Excel
   row/column limits. It applies final widths after stream exhaustion.
5. `close` finalizes the temporary XLSX, applies target permission bits, and
   replaces the target.

The [streaming and autofit architecture](20260831-v1.0-neatxlsx-streaming-autofit-architecture.md)
documents logical body sampling, delayed width assignment, physical splitting,
and the native failure boundary. The private native surface now contains one
canonical batch writer; the former direct DataFrame, IPC, and dual-stream paths
have been removed.

Header cells merge format fields in the order workbook header, custom-header
row patch, then logical data-column patch. Body column planning remains a
separate path. Both column-keyed plans are rebased on every physical column
slice, and row pagination writes the same resolved header plan on each repeated
header. Python rejects nonempty header-column patches with merged headers before
the bridge because a merged range cannot preserve distinct column styles. A
shared core preflight repeats that compatibility check before worksheet
creation in the canonical native entrypoint, so a rejected private call cannot
consume a sheet name or leave an empty worksheet.

## Transaction boundary

Normal completion is complete-file replacement, not power-loss durability.
Atomicity depends on same-filesystem rename support; CephFS and NFS semantics
depend on their mounts and servers. The library doesn't promise fsync,
ownership, ACL, or extended-attribute preservation.

Existing POSIX permission bits are retained. New files use `0o666 & umask`.
Generation failure aborts. If final replacement fails, the completed temporary
file remains available to retry `close()` or discard with `abort()`. A process
crash can leave a hidden `.neatxlsx-*` sibling; one process never deletes
another process's orphan.

During generation, storage may include the old target, the new workbook, and
rust_xlsxwriter worksheet temporaries. All temporary data defaults to the
target directory.

## ZIP64 and limits

`use_zip64=True` is the reliability default. Even a small file then requires a
ZIP64-capable reader. There is no `"auto"` mode: the uncompressed OOXML size
isn't known when streaming entry headers are emitted. Callers may opt out for
legacy readers.

## Origin and independence

The initial XLSX implementation was copied from axiomkit so both repositories
could evolve independently. axiomkit retains its original implementation and
does not depend on neatxlsx. Critical fixes are backported manually when
needed; there is no shared source or synchronized-release contract.

The [caller migration guide](../how-to-guides/20260831-v1.0-migrate-axiomkit-xlsx.md)
maps old API concepts to current neatxlsx calls. The
[axiomkit XLSX archive](../archive/axiomkit-xlsx/README.md) preserves the original
streaming plan, rename and ZIP64 notes, and benchmark evidence with a pinned
source revision. Its API names and performance numbers are historical only.
