# Display-Accurate Single-Pass Autofit Optimization Plan

Version: v1.0
Date: 2026-09-01
Status: implementation and local correctness/distribution/LibreOffice evidence landed; performance gate failed; Windows Excel, emoji, release matrix, CI, and publication remain pending

Current release decision: the user accepted the recorded performance costs on
2026-09-08 for 0.2.1. See [release readiness](20260908-v1.0-single-pass-release-readiness.md).
Historical performance verdicts below remain unchanged; Windows Excel and
distribution verification remain required.

## Authority and scope

This plan is the accepted follow-on to the
[single-pass autofit implementation plan](20260901-v1.0-single-pass-autofit-implementation-plan.md).
It replaces the width-estimation layer without changing the one-stream input
contract, logical-table sampling, physical-sheet splitting, transactional
replacement, or the public `Autofit` configuration.

The change may alter generated column-width values. The compatibility target is
more accurate displayed results with unchanged `mode`, `max_rows`, `min_width`,
`max_width`, and `padding` configuration and meaning. Exact `<col width="...">`
values and XLSX bytes are not compatibility contracts for this change.

This plan does not authorize package publication, tagging, or a
`rust_xlsxwriter` upgrade. The optimization is a prerequisite for the next
release that contains single-pass body autofit, but release remains a separate
authorized boundary.

## Research conclusion

`rust_xlsxwriter 0.90.2` already exposes `cell_autofit_width()`, which estimates
Calibri 11 string width from per-ASCII-character Excel metrics and includes the
standard seven-pixel cell padding. Its `Worksheet::set_column_autofit_width()`
API also writes Excel's `bestFit` column metadata.

The `enhanced_autofit` feature added in `rust_xlsxwriter 0.93.0` uses
[`ssfmt`](https://github.com/ketbra/ssfmt) to account for formatted numbers and
dates. It does not provide a reusable public display-width function and remains
coupled to `Worksheet::autofit()`. In constant-memory mode that worksheet scan
cannot observe rows already flushed to the worksheet temporary file. It also
calculates each physical worksheet independently rather than preserving
neatxlsx's logical-column width across row pages and column splits.

The accepted composition is therefore:

```text
final cell value + final number format
    -> ssfmt display text
    -> rust_xlsxwriter::cell_autofit_width()
    -> narrow evidence-backed non-ASCII fallback when required
    -> LogicalAutofitTracker maximum
    -> unchanged padding/min/max policy
    -> Worksheet::set_column_autofit_width()
```

This reuses the two domain-specific mechanisms while keeping only the
streaming, sampling, configuration, and split-sheet policy that neatxlsx must
own.

## Confirmed decisions

1. The new estimator becomes the only production autofit implementation. There
   is no public legacy metric, enhanced-mode switch, environment variable, or
   Cargo feature that preserves two selectable width semantics.
2. Add a direct `ssfmt 0.1.2` dependency with default features disabled. Do not
   enable `rust_xlsxwriter/enhanced_autofit` and do not bundle a
   `rust_xlsxwriter` upgrade with this work.
3. Use every final number format that `ssfmt` can parse. Do not maintain a
   neatxlsx allowlist of Excel formats. Add a narrow exception only after a
   reproducible Excel mismatch, and report the formatter issue upstream rather
   than implementing a parallel formatter.
4. A format parse or compatibility failure falls back to the current
   deterministic width estimate and does not fail workbook generation. Internal
   invariant failures remain writer errors.
5. Use a per-write formatter cache keyed by the exact final format string.
   Cache both parsed and unsupported results. Do not call the `ssfmt::format()`
   convenience API in the cell hot path because it uses a global mutex-backed
   cache.
6. Write `bestFit=1` through `set_column_autofit_width()`. Initial generated
   widths still obey `padding`, `min_width`, and `max_width`; `max_width` does
   not promise to constrain a later Excel expansion caused by a user increasing
   the digits in an edited numeric cell.
7. Keep the current Excel 1900 date system and en-US base locale. This change
   adds no locale or 1904 date-system API. Locale-bearing user format strings
   are passed to `ssfmt` and use the same fallback boundary when unsupported.
8. Accuracy is based on Calibri 11 metrics. Do not add system-font discovery,
   font-file parsing, or a cross-platform text-layout engine. Custom fonts and
   font sizes remain deterministic approximations.
9. CJK is part of the visual acceptance set. Upstream 0.90.2 and 0.99.0 have no
   CJK-specific autofit handling: every non-ASCII character outside the ASCII
   table receives a generic eight-pixel width. LibreOffice 6.4 Linux bounding
   boxes established a narrow measured safety floor: add four pixels only for
   U+3000–303F, U+3040–30FF, U+4E00–9FFF, U+AC00–D7AF, and U+FF01–FF60. The
   resulting twelve-pixel floor is not a complete CJK implementation; emoji,
   accented Latin, extensions, and compatibility ideographs retain upstream
   behavior. Windows Excel remains a calibration gate. Do not use terminal
   display width as a proxy for font width or hand-maintain a complete Unicode
   range table.
10. Preserve the current merged-header width ownership. This work improves the
    measurement under that rule but does not distribute a merged label across
    its spanned columns.

## Target internal boundary

Keep the existing `plan_column_formats()` precedence and extend its consumers
rather than constructing a second format planner. `XlsxSheetRuntime` retains a
width-format entry beside every normal and scientific `rust_xlsxwriter::Format`:

```rust
enum WidthFormat {
    Plain,
    ExcelNumberFormat(Rc<ssfmt::NumberFormat>),
    Fallback,
}

struct XlsxSheetRuntime {
    data_formats_by_col: Vec<Format>,
    scientific_formats_by_col: Vec<Format>,
    data_width_formats_by_col: Vec<WidthFormat>,
    scientific_width_formats_by_col: Vec<WidthFormat>,
    // Existing runtime fields remain.
}
```

The implementation uses `Rc` because the cache is confined to one write on the
same thread. The exact Rust shape may be reduced during implementation, but these invariants
must hold:

- the write format and width format come from the same final
  `CellFormatPatch`;
- normal versus scientific selection happens once per cell and selects both
  representations together;
- repeated row pages reuse parsed number formats;
- unsupported formats are not reparsed per cell; and
- the estimator does not retain cell or row data.

The estimator works in pixels. The public configuration retains Excel
character-unit semantics. Convert the existing integer `padding`, `min_width`,
and `max_width` limits to the corresponding Calibri 11 pixel domain once, apply
the bounds there, then pass the final pixel width to
`set_column_autofit_width()`. Account for the seven pixels already included by
`cell_autofit_width()` so user padding is not double-counted.

## Stage 1: freeze contracts and evidence

Before production edits:

1. Record current and candidate widths for proportional Latin text, CJK,
   mixed-width text, emoji, booleans, missing-value text, integer, decimal,
   scientific, percent, currency, fraction, date, datetime, time, and duration.
2. Include explicit column number formats, role overrides, scientific fallback,
   `min_width`, `max_width`, and non-default `padding`.
3. Freeze an acceptance workbook that includes multi-row and merged headers,
   row pagination, column splitting, and the `max_rows - 1`/`max_rows` sampling
   boundary.
4. Retain raw output manifests and worksheet XML. Generated XLSX files remain
   test or release artifacts unless a compact reviewed specimen is deliberately
   admitted.
5. Add and lock `ssfmt` only in the implementation commit; verify its MIT OR
   Apache-2.0 license, pure-Rust build, disabled `chrono` feature, and resulting
   sdist/wheel contents.

## Stage 2: add the minimal estimator seam

1. Add an internal `DisplayWidthEstimator` owned by `neatxlsx_core`.
2. Retain or derive width formats from the existing final format patches. Do
   not refactor the public format contract or duplicate format precedence.
3. Add one per-write cache for parsed and unsupported format strings.
4. Move width observation after normal/scientific format selection, before the
   cell is written and flushed.
5. Preserve `LogicalAutofitTracker` as the one global logical-column tracker.
6. Preserve current results initially through a characterization seam so the
   estimator integration and width-policy replacement can be reviewed
   separately. Do not expose that temporary comparison seam in production.

## Stage 3: replace the production metric atomically

1. Generate display text with the cached `ssfmt::NumberFormat` for numeric,
   date, datetime, time, duration, and scientific cells with final number
   formats.
2. Measure strings, formatted numeric display text, booleans, and configured
   missing-value text with `cell_autofit_width()`.
3. Exercise the CJK workbook in Excel and LibreOffice. The Linux LibreOffice
   6.4 evidence has landed a narrowly scoped twelve-pixel floor for the five
   measured scalar ranges; Windows Excel still requires calibration. Do not
   broaden the floor without new evidence.
4. Apply the existing logical-row sampling before any `ssfmt` or width work.
   With default `max_rows=20_000`, row 20,000 and later perform no body width
   formatting. `max_rows=None` retains full-table sampling.
5. Convert and apply user padding and min/max bounds once, then set every
   physical occurrence of a logical column through
   `set_column_autofit_width()`.
6. Remove obsolete general-path character-count and handwritten formatted-value
   estimates. Retain only the isolated compatibility fallback and any measured
   non-ASCII fallback.

No release may contain the temporary estimator seam with only part of this
stage activated.

Implementation note: the seam was landed without a public comparison mode. It
uses `NumberFormat::try_format()`; parse errors are cached as unsupported, and
value-specific format errors fall back only for that cell so a date-range error
cannot disable a valid formatter for later values.

## Stage 4: correctness, visual, and performance gates

### Structural and semantic tests

- Unit-test upstream pixel examples, proportional extremes such as repeated
  `W` and `i`, pixel/character policy conversion, padding, min/max clamping,
  cache hits, cached unsupported formats, and parse fallback.
- Test built-in neatxlsx formats and representative explicit formats:
  decimal scale, grouping, percent, currency, fraction, positive/negative/zero
  sections, scientific, date, datetime, time, duration, conditions, colors,
  and locale tags.
- Include negative and boundary temporal serials, rounding boundaries, zero,
  negative zero, large finite values, precision-as-text integers, missing
  values, and configured non-finite replacements.
- Prove that `none` performs no estimator initialization, `header` performs no
  `ssfmt` formatting, and body work stops at the global logical `max_rows`
  boundary even across record batches and row pages.
- Prove that the same logical source column has the same width on every row
  page and is mapped correctly through column splits.
- Preserve values, formulas-as-literal-strings, types, number formats, style
  indexes, merged ranges, freeze panes, reports, warnings, ZIP64 defaults, and
  transactional replacement behavior.

### Narrow output-difference contract

Keep raw ZIP member hashes. After normalizing only the existing generated core
timestamps, allow candidate differences solely in worksheet `<cols>` nodes.
Parse and assert those nodes separately:

- expected `width`, `min`, `max`, `bestFit=1`, and `customWidth=1`;
- no `bestFit` or column-width change for `mode="none"`; and
- identical non-`<cols>` worksheet XML and identical other ZIP members.

Do not ignore a whole worksheet part to accept expected width changes.

### Performance gates

Use the existing interleaved, fixed-sample benchmark protocol with release
binaries and predeclared sample counts:

| Scenario | Acceptance budget |
| --- | --- |
| `none` | 95% interval excludes a total-wall regression of 3% or more |
| `header` | 95% interval excludes a total-wall regression of 3% or more |
| `body/all`, default `max_rows=20_000` | 95% interval excludes a total-wall regression of 3% or more |
| `body/all`, `max_rows=None` | median total-wall regression at most 10%, with interval upper bound at most 15% |

Profile before accepting any failed gate. Formatting and width work must remain
linear in sampled cells, and additional retained memory must remain
`O(logical columns + distinct final format strings)`.

### Application evidence

Before replacing the released estimator, inspect the acceptance workbook in:

1. LibreOffice, including open/save/readback; and
2. desktop Windows Excel, including representative visual inspection and an
   edit that increases the digits of a best-fit numeric cell.

Record the application versions and observed boundaries. OOXML or openpyxl
inspection alone cannot establish displayed-width accuracy. If Windows Excel
is unavailable, report the missing gate and do not claim visual acceptance is
complete.

## Stage 5: documentation convergence and release readiness

After implementation and evidence:

1. Update the streaming/autofit architecture with the estimator ownership,
   pixel policy, formatter fallback, `bestFit`, and CJK/font boundaries.
2. Update the test plan and benchmark protocol with the narrow `<cols>` oracle,
   application canary, and split performance budgets.
3. Update caller documentation without adding configuration. State that an
   upgrade may change concrete column widths while keeping `Autofit` settings
   unchanged.
4. Update release notes with the dependency, intended display improvement,
   `bestFit` editing behavior, fallback boundary, and verified applications.
5. Run the smallest affected tests first, then the complete repository gate,
   distribution matrix, `git diff --check`, and final status inspection.
6. Treat publication as a separate authorization after exact-head CI and the
   release bundle gates pass.

## 2026-09-01 execution result and remaining gates

The implementation is landed locally with `ssfmt 0.1.2`, the shared
`cell_autofit_width()` estimator, the narrow measured East Asian fallback,
pixel-domain policy, and `bestFit`. The compact evidence record is
[display-accurate autofit evidence](../benchmarks/results/20260901-display-accurate-autofit/README.md).

Local evidence includes `pdm run check`, 27 focused Rust tests, 132 Python
tests with two skips and two explicit large checks, plus local wheel and
sdist-from-wheel validation. The LibreOffice 6.4 canary passes for its tested
Chinese, Japanese, Korean, and fullwidth strings; it also records the retained
ZIP64 reader concern and Calc round-trip normalization.

The clean single-pass-to-display-estimator comparison fails the predeclared
performance gate: only one of six scenarios passes. The older ABI v5/v6
comparison remains only a mixed-upgrade diagnostic. Do not infer the present
estimator's cost from it. The pending gates are Windows Excel visual and
`bestFit` edit-expansion calibration, emoji/font evidence, release matrix and
exact-head CI, and an authorized release decision. No publication occurred.

## Deferred layout and platform boundaries

### Merged headers

The current tracker attributes a merged header label according to the existing
logical-cell ownership rather than distributing it over the merged span. This
work deliberately preserves that behavior. A later layout proposal must choose
and visually validate one of these policies:

- ignore merged labels for autofit, similar to common Excel autofit limits;
- divide the label width across the merged columns; or
- preserve current column maxima and distribute only the missing total width.

No option is selected by this plan, and implementation documentation must not
claim merged-header width allocation is solved.

### Fonts and platforms

The upstream metric is calibrated to Calibri 11 and does not adapt to cell font
or font size. Excel for Windows, Excel for macOS, and LibreOffice can render the
same stored width differently. CJK also depends on the application's font
fallback. The bounded canary records representative behavior without claiming
a general font-layout solution.

### Future autofilter support

neatxlsx does not currently expose worksheet autofilters. If that capability is
added, the autofit planner must account for the filter dropdown width; the
upstream helper does not add that icon allowance automatically.

### Future locale and date-system support

If the writer later exposes a non-en-US base locale or the Excel 1904 date
system, the display estimator must derive matching `ssfmt::FormatOptions` from
the same workbook plan. A second independent estimator setting is prohibited.

Expected tests and evidence:

- focused Rust estimator and tracker tests;
- integration/reference cases for formats, CJK, splits, `bestFit`, and narrow

- the interleaved benchmark analyzer or scenario manifest only where the new

No Python, PyO3, or public API change is expected. If implementation evidence
contradicts that inventory, stop and review the expanded boundary before
editing those layers.

## Acceptance and rollback

The optimization is complete only when:

- input is still consumed once for every autofit mode;
- the new estimator is the sole production metric with internal fallback only;
- final write formats and width formats share the same precedence result;
- the structural, visual, performance, distribution, and complete repository
  gates pass; and
- the documented limitations match the retained behavior.

Rollback is a commit/release rollback to the previous estimator. Do not retain
a dormant public legacy mode. A failed `ssfmt`, CJK, performance, wheel, or
Excel canary preserves the current single-pass implementation and records the
specific rejected candidate rather than weakening a gate.
