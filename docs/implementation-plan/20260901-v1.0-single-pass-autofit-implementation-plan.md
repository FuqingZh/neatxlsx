# neatxlsx Single-Pass Body Autofit Implementation Plan

Version: v1.2
Date: 2026-09-01
Status: implementation functionally validated; performance gate not met; branch preserved

## Objective and completion claim

Replace all production two-pass XLSX batch writing with one Arrow input stream.
`none`, `header`, `body`, and `all` must normalize and write each input cell once,
track sampled logical-column widths online, apply widths after input exhaustion,
and preserve the intended workbook, report, transaction, and packaging
contracts.

This delivery also retires the unused native DataFrame/IPC paths and the private
bridge methods that sustain duplicate writer implementations. The final Python
and PyO3 bridge exposes one canonical batch method. The retained pure split
planner supplies final physical-sheet order, names, warnings, and intervals; no
runtime fallback re-evaluates the input.

The change is complete only when all of the following are demonstrated:

- the public write path creates and consumes one batch stream for every autofit
  mode;
- no production Python, PyO3, or Rust core two-pass writer remains;
- `body` and `all` preserve logical-table `max_rows` sampling and share one
  normalized cell semantic with actual XLSX writes;
- physical worksheet order, names, intervals, warnings, formats, and reports
  match the reviewed compatibility fixtures except for individually approved
  autofit corrections caused by the former normalization split;
- errors after the first native workbook mutation poison the native writer,
  while errors proven to occur before mutation remain recoverable;
- the original target survives every generation failure and there is no
  transparent two-pass retry;
- real Excel row and column overflow outputs pass independently;
- locked, minimum-supported, and latest-stable Polars validation passes;
- a release-build Parquet LazyFrame benchmark proves the intended input-work
  reduction without regressing control paths beyond measured noise; and
- package publication, tagging, and version promotion remain outside this
  implementation boundary.

## Execution outcome

The single-stream implementation, v6 bridge transition, compatibility
fixtures, finalization poison tests, real row/column boundaries, and locked,
minimum, and latest Polars lanes are complete. The frozen ABI v5 fixture
acceptance guard is enforced at the actual fixture-mutation boundary, including
direct Python callers.

The performance completion condition is not met. In the retained strict serial
huge profile, LazyFrame `body` improves beyond its frozen allowance, LazyFrame
`all` remains within noise, and LazyFrame `none` regresses beyond its allowance.
The default profile has no regression outside noise but does not establish the
required `body/all` improvements. See the
[comparison record](../benchmarks/results/20260901-single-pass-autofit/comparison.md)
for the raw inputs, formula, classifications, exclusions, and limitations.
The implementation branch is therefore preserved for review without a
performance or release claim.

## Confirmed decisions

1. **Current remote main is the baseline.** The reviewed workspace was on local
   `main` `fa2be10`, while the observed `origin/main` and tag `0.2.0` were
   `85c3519`. Execution begins with a fresh fetch and authoritative readback.
   Existing documentation changes are transplanted as a patch onto an AO-owned
   worktree based on the then-current remote main; the stale local branch is not
   merged into it.
2. **The two-pass implementation is retired, not retained as fallback.** No
   call may silently re-evaluate a consumed, one-shot, or nondeterministic
   source. Rollback means reverting the implementation or using the previous
   released package.
3. **Compatibility evidence is frozen before deletion.** Canonical JSON/OOXML
   manifests generated from the exact two-pass baseline replace a runtime
   two-pass oracle. Ordinary tests never rewrite them.
4. **The private bridge advances atomically to v6.** Python expectations, Rust
   exports, stubs, mismatch tests, and installed-package tests change together.
   Its only writer method is named `write_sheet_batches(batches, ...)` and takes
   one input stream.
5. **Unused native paths are removed.** Delete the PyO3 direct DataFrame method,
   the dual-stream batch method, Rust two-pass planner/orchestrator, and core
   DataFrame/IPC writer. Remove the resulting unused core `polars`/IPC
   dependency. The PyO3 crate temporarily retains Rust Polars only for current
   header-grid conversion; Arrow-native header conversion is a separate task.
6. **Native post-mutation failure is terminal.** Once a logical write has
   changed workbook state, any later error sets the native writer to poisoned.
   A poisoned writer rejects write and close and is disposed by the Python
   abort path. Preflight validation that has not touched backend state remains
   recoverable.
7. **There is one normalized cell semantic.** The value, warning, numeric role,
   scientific decision, and write type used by the width tracker are the same
   semantic object used by the worksheet writer. Do not retain legacy planner
   and writer normalization branches.
8. **Autofit remains approximate.** This delivery does not add a full Excel
   number-format, font-metric, or locale renderer. Existing estimator limits
   remain explicit. Only width corrections directly explained by eliminating
   the old normalization divergence may update reviewed fixtures.
9. **Autofit sampling uses absolute logical coordinates.** The tracker receives
   `(row_abs, col_abs)` and checks the global sampling window. It does not
   increment a per-runtime or per-physical-sheet row counter.
10. **Physical page identity uses stable starts.** Registry identity is
    `(row_start, col_start, col_end)`. The static planner supplies final
    `row_end`; the actual dynamic report end must equal it. A provisional
    runtime row limit is never used as final identity.
11. **Zero-row and zero-column behavior stay distinct.** A zero-row table with
    a nonempty schema succeeds and creates the existing empty physical sheet.
    A zero-column input retains the current `WriteError` plus abort behavior;
    changing it to recoverable preflight validation is out of scope.
12. **The dependency remains pinned.** Keep `rust_xlsxwriter 0.90.2`; do not
    enable newer autofit features. A dependency upgrade repeats the late-width,
    rename, reorder, OOXML, split, and fixture validation separately.
13. **Release is separate.** The implementation branch is based on package
    `0.2.0` and advances only the paired private bridge. A later authorized
    release boundary may publish `0.2.1`; this plan creates no tag or package
    publication.

## Constraints

- Preserve the public `Workbook.write_sheet()` signature, `Autofit` options,
  defaults, and caller-facing return types.
- Preserve `max_rows=20_000` as the first 20,000 body rows of the logical table.
  `max_rows=None` removes the sampling limit.
- Preserve literal string writes, ZIP64 defaults, value-conversion warnings,
  format precedence, freeze panes, repeated headers, custom header behavior,
  and transactional target replacement.
- Preserve column-first, then row split ordering, `_1` through `_N` planned
  names, unique-name collision behavior, and the exact overflow warning.
- Do not buffer the full input. Retained state is bounded by logical columns,
  physical worksheets, formats, the current Arrow batch, and underlying writer
  state; it does not retain prior row bodies.
- Keep the axiomkit archive immutable.
- Do not change package version, create a tag, publish artifacts, or upgrade
  `rust_xlsxwriter` in this delivery.

## Evidence supporting the design

The pinned `rust_xlsxwriter 0.90.2` constant-memory implementation stores
column widths as worksheet metadata and emits that metadata before copying row
data from worksheet temporary files into `<sheetData>`. A local exact-version
probe successfully:

1. wrote rows that flushed earlier rows to temporary files;
2. assigned widths after all rows were written;
3. reordered multiple worksheets and assigned final names; and
4. saved and read back the expected values, widths, names, and order.

The mechanism therefore supports delayed width assignment. The remaining work
is neatxlsx state management and compatibility finalization.

### Comparable streaming-writer research

A 2026-09-01 review of official documentation and upstream source found a
useful online-width tracking precedent, but no library that also solves
unknown-height automatic row/column splitting while preserving a pre-existing
column-first physical-sheet contract:

- [Apache POI SXSSF](https://poi.apache.org/apidocs/4.0/org/apache/poi/xssf/streaming/SXSSFSheet.html)
  requires columns to be registered before rows are written, updates retained
  best-fit maxima as rows pass through the streaming window, and can size a
  column after earlier rows have been flushed. Its
  [AutoSizeColumnTracker](https://apache.googlesource.com/poi/+/cba8f2740f45a6f5e906dc807f8d50c7da8b59a3/trunk/poi-ooxml/src/main/java/org/apache/poi/xssf/streaming/AutoSizeColumnTracker.java)
  is the closest precedent for keeping width tracking independent from row
  storage.
- [Python XlsxWriter constant-memory mode](https://xlsxwriter.readthedocs.io/working_with_memory.html)
  flushes the previous row as the next row is written. Its current autofit
  implementation does not cover constant-memory mode; the upstream
  [feature discussion](https://github.com/jmcnamara/XlsxWriter/issues/1125)
  proposes a row-flush hook that retains a maximum width per column.
- [Excelize StreamWriter](https://xuri.me/excelize/en/stream.html) requires
  `SetColWidth` before the first `SetRow`, so it cannot derive body widths from
  an unknown input stream.
- [openpyxl write-only mode](https://openpyxl.readthedocs.io/en/stable/optimized.html)
  requires metadata that precedes cell data to be established before cells are
  appended, so it does not provide a delayed-width model.
- [rust_xlsxwriter autofit guidance](https://rustxlsxwriter.github.io/worksheet/autofit.html)
  supports retaining a calculated maximum and applying an explicit width. The
  neatxlsx-specific probe remains necessary for late width, rename, and reorder
  behavior.

None supplies a reusable implementation for this full combination:

```text
unknown total rows
    + automatic Excel row and column overflow splitting
    + dynamically created constant-memory worksheets
    + final column-first order, names, warnings, and report intervals
```

The adopted design therefore combines a POI-style independent logical width
tracker with a separate physical-sheet registry and neatxlsx's static split
planner.

## Target architecture

### NormalizedCell

Perform Arrow extraction once and create one semantic cell representation:

```text
NormalizedCell
  value
  warning
  column value kind
  numeric and integer role
  scientific decision
  write/display format metadata
```

Both width estimation and the worksheet write consume this representation.
The estimator remains approximate; it does not become an Excel rendering
engine.

### LogicalAutofitTracker

```text
LogicalAutofitTracker
  mode
  max_rows
  header_widths_by_col
  body_widths_by_col

observe(row_abs, col_abs, normalized_cell)
finish() -> final logical widths
```

`observe()` uses the absolute logical row:

```text
max_rows is None or row_abs < max_rows
```

It never restarts for a batch, row page, or column part and never advances a
mutable row counter once per physical worksheet.

### PhysicalSheetRegistry

Each dynamically created worksheet is registered as:

```text
key: (row_start, col_start, col_end)
value:
  worksheet_index
  report_index
  temporary_name
  actual_row_end
```

The key is stable at creation. Runtime overlap code may use a theoretical
`row_start + max_data_rows` upper bound, but that bound is not identity or final
report state.

### Finalization

After the final input batch:

1. Ask the retained static planner for canonical slices using final row count,
   logical width, header height, and requested name.
2. Iterate canonical column-first slices and remove exactly one matching entry
   from `PhysicalSheetRegistry` using `(row_start, col_start, col_end)`.
3. Cross-check the dynamically observed actual `row_end` against the planner's
   final `row_end`.
4. Apply logical-column widths to every saved worksheet index, rebased to local
   columns.
5. Release only temporary names belonging to the current logical write.
6. Reserve final unique names in canonical order and rename worksheets.
7. Reorder only the contiguous worksheet segment appended by this logical
   write; earlier logical sheets do not move.
8. Rebuild report slices in canonical order and reuse the static planner's
   exact overflow warning.
9. Require the registry to be empty, proving no orphan physical sheet remains.
10. Sort warnings and append the report only after all checks succeed.

Apply widths before reordering so saved worksheet indices remain stable.
Duplicate or missing registry keys, boundary mismatch, rename failure, width
failure, or permutation failure poisons the native writer.

## Execution plan

### Slice 0: move to authoritative main and establish ownership

1. Fresh-fetch the remote and record its exact main SHA and package version.
2. Verify AO daemon readiness, repository adoption, owner state, writable
   worktree, and single-writer containment.
3. Export the current documentation changes as a reviewable patch without
   merging stale local main.
4. Create or route to the authorized AO worker based on the fresh remote main.
5. Apply the documentation patch, resolve release-state conflicts against
   0.2.0, and re-run documentation validation.
6. Record source paths, native extension path, build profile, distribution
   version, lockfile, and dirty state.

Stop if the writable workspace or loaded native extension cannot be tied to
the authoritative owner and source SHA.

### Slice 1: freeze the two-pass baseline

Before changing writer code, add a deterministic fixture generator using the
current public path and generate canonical manifests from the exact baseline.
Each manifest records source SHA, scenario inputs, policy values, and canonical
outputs. Commit the reviewed fixtures separately.

Cover:

- `none`, `header`, `body`, and `all`;
- default, bounded, and `None` `max_rows`;
- batch-boundary sampling;
- empty rows with a nonempty schema;
- missing values and non-ASCII missing markers;
- integer, decimal, float, boolean, string, date, datetime, time, and duration;
- precision and temporal text fallbacks;
- scientific notation and format overrides;
- custom and merged headers;
- duplicate logical sheet names;
- row and column split planning; and
- multi-sheet report and warning order.

Canonical outputs include worksheet names/order, report intervals, warnings,
cell values/types, column-width XML, styles/number formats, merges, freeze
panes, and workbook relationships needed by the contract. Do not commit XLSX
binaries. Fixture updates require an explicit command and reviewed reason;
ordinary tests are read-only.

### Slice 2: implement one semantic cell and online tracking

Primary files:

- `crates/neatxlsx_core/src/writer/value.rs`
- `crates/neatxlsx_core/src/writer/stream.rs`

Introduce `NormalizedCell` and make existing single-stream writing produce it
from one Arrow extraction. Feed the same normalized semantics to
`LogicalAutofitTracker` and cell rendering. Use absolute `(row_abs, col_abs)`
coordinates for sampling and width indexing.

Compare candidate widths with frozen fixtures. Any difference must be isolated
to a named legacy normalization divergence, covered by a focused test, and
approved in the fixture diff. Do not expand into font-aware or arbitrary
number-format rendering.

### Slice 3: implement registry finalization and poison state

Primary files:

- `crates/neatxlsx_core/src/writer/stream.rs`
- `crates/neatxlsx_core/src/writer/mod.rs`
- `crates/neatxlsx_core/src/util.rs` only for a focused pure planning/name helper

Add `PhysicalSheetRegistry`, temporary-name bookkeeping, final width assignment,
canonical mapping, segment permutation, final naming/report construction, and
all consistency checks.

Replace the writer's boolean close marker with an explicit state model such as:

```text
Open
Poisoned
Closed
```

Preflight errors leave `Open`. Errors after the first workbook mutation set
`Poisoned`; subsequent write and close calls fail. Report access returns only
previously completed logical writes. Dropping/aborting the writer must release
constant-memory worksheet temporary resources.

### Slice 4: retire duplicate production paths and advance bridge v6

Delete:

- the Rust RecordBatch two-pass plan/write orchestrator;
- `crates/neatxlsx_core/src/writer/plan.rs` and its module wiring;
- core DataFrame and IPC writer entrypoints and their dedicated helpers;
- the core `polars`/IPC dependency;
- PyO3 `write_sheet(body, ...)`;
- PyO3 dual-stream `write_sheet_batches(scan, write, ...)`; and
- tests and fakes whose only purpose is exercising removed private methods.

Rename the only native path to canonical names:

```text
PyO3: write_sheet_batches(batches, ...)
Rust: write_sheet_from_record_batch_results(batches, ...)
```

Atomically change:

- Rust bridge ABI/contract `5 -> 6`;
- Python expected ABI/contract;
- `_native.pyi`;
- backend protocol;
- v5/v6 mismatch tests; and
- installed wheel/package smoke assertions.

Do not change the public Python method signature. Keep the PyO3 Polars
dependency only for existing header-grid conversion.

### Slice 5: route the public path and prove one evaluation

Modify `python/neatxlsx/writer.py` so every autofit mode constructs one
`collect_batches()` source and calls the v6 `write_sheet_batches()` method.
There is no branch that constructs two streams and no exception fallback that
constructs a replacement stream.

Add a one-shot source whose second evaluation would fail, plus instrumentation
that proves one stream is created and fully consumed. Read back the XLSX and
report so routing evidence alone cannot pass.

### Slice 6: performance and compatibility evidence

Extend the benchmark harness with a deterministic Parquet LazyFrame scenario.
Generate the Parquet fixture before timing; time
`scan_parquet -> projection/filter/expression -> XLSX`. Retain DataFrame cases
to isolate writer overhead.

Run baseline and candidate release binaries with identical inputs, files,
policies, chunk sizes, warmups, repetitions, filesystem, and output validation.
Measure baseline variance first and freeze the noise rule before judging the
candidate. Require:

- `body/all` LazyFrame candidate improvement beyond measured noise;
- no `header/none` regression beyond measured noise;
- output manifest parity or reviewed narrow width corrections; and
- raw measurements, environment, binary identity, and output sizes retained.

A reduced conceptual pass count is not a performance result.

### Slice 7: synchronize documentation

After code and validation land, update current architecture, public bridge
contract, testing plan, benchmark protocol, README indexes, and release-facing
notes to state:

- one production Arrow stream;
- bridge v6 and removed private methods;
- tracker/registry/finalization state;
- poison and no-fallback behavior;
- estimator limits;
- frozen fixture provenance;
- real split and Polars validation lanes; and
- 0.2.1 publication remains a separate boundary.

Do not modify the axiomkit archive or represent the implementation as already
published.

### Registry and finalization

2. an exactly full row page;
3. an incomplete final row page;
4. zero rows with a nonempty schema;
5. multiple column parts;
6. synthetic combined row/column parts reordered from row-first creation to

9. width rebasing on all row pages;
10. earlier logical sheets remaining stationary;
11. temporary and final name collisions;
12. exact overflow warning and report order; and

### Failure state and transaction

Inject errors:

- before workbook mutation;
- after worksheet creation;
- after flushed row writes;
- during final width assignment;
- during name reservation/rename;
- during permutation/final report construction; and
- during save/commit.

Verify preflight recovery, post-mutation poison, close/write rejection when
poisoned, previous successful report visibility, Python abort, target content
and permission preservation, and temporary resource cleanup. Verify no runtime
fallback or second source evaluation occurs after unknown-outcome failures.

### Public and bridge contract

Verify:

- public `Workbook.write_sheet()` signature and defaults are unchanged;
- v5 native plus v6 Python and v6 native plus v5 Python both fail explicitly;
- v6 exports exactly the intended canonical writer method;
- removed private methods are absent from native and stub surfaces;
- zero-column input retains `WriteError` plus abort;
- zero-row nonempty-schema input succeeds in every autofit mode;
- formula-looking strings remain literal;
- format/header behavior and reports match fixtures; and
- wheel imports load the paired native binary from the tested artifact.

### Real Excel boundaries

These are required delivery gates, not optional evidence:

1. one-column data crossing the real 1,048,576-row worksheet boundary;
2. one-row data crossing the real 16,384-column worksheet boundary; and
3. synthetic combined overflow to prove column-first permutation without
   constructing an impractical Cartesian workbook.

If either independent real-boundary run cannot complete on the authorized host,
delivery is blocked rather than reported as complete with an unchecked risk.

## Delivery and rollback gates

Do not delete baseline behavior before its canonical fixtures are committed.
Do not switch the Python route before core tracker, registry, finalization, and
poison tests pass. Bridge v6 changes land as one paired unit.

Stop and preserve the branch if:

- authoritative main, AO owner, or tested binary identity is uncertain;
- a physical page cannot be mapped exactly once by its stable key;
- actual and planned final row bounds differ;
- earlier pages do not receive final logical widths;
- name allocation, sheet order, warning order, or report intervals diverge
  without an approved contract correction;
- a post-mutation error leaves the writer closable or writable;
- a second input evaluation or runtime fallback is observed;
- either real Excel overflow gate fails or cannot run;
- minimum or latest stable Polars fails the required lane;
- performance controls regress beyond the frozen noise rule;
- the target or permission bits change after generation failure; or
- a required repository gate fails for first-party code.

Rollback is commit/release rollback to the previous implementation. It is never
a per-call attempt to replay the input through deleted two-pass code.
