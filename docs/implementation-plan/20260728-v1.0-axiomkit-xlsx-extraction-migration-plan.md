# axiomkit XLSX Extraction Migration Plan

Version: v1.0  
Date: 2026-07-28  
Status: completed

## Goal

Create an independent neatxlsx repository without changing axiomkit, first
proving behavior-equivalent extraction and then replacing the copied public API
with the agreed neatxlsx contract.

## Checkpoints

### Behavior-equivalent copy

Copy the two Rust XLSX crates, Python facade, four XLSX test files, and
benchmark/profile scripts. Change only package, module, bridge, and build paths.
Accept when the original 35 Python tests and both Rust crates pass.

Checkpoint commit: `feat: extract behavior-equivalent XLSX writer`.

### neatxlsx public API

Replace the old API directly with `Workbook`, public value objects,
transactional lifecycle, immutable reports, and the new selector/inference
contract. Reorganize tests by behavior layer; add documentation, repository
harness, package validation, and CI/release workflows.

Checkpoint commit: `feat!: establish neatxlsx public API and delivery contract`.

## Non-goals

- remove or redirect axiomkit XLSX code;
- add pandas, PyArrow, Pydantic, XlsxWriter, or remote filesystem dependencies;
- provide existing-workbook editing or full report composition;
- publish a package, tag, container, or remote repository during local work.

## Rollback

The first local commit is a reconstructable parity checkpoint. The second
commit can be reviewed or reverted independently. axiomkit is unaffected.

## Documentation completion (2026-08-31)

The initial extraction copied implementation, tests, and measurement scripts,
but did not include axiomkit's XLSX migration notes, single-pass plan, or
benchmark documentation/results. These are now retained in the
[axiomkit XLSX archive](../archive/axiomkit-xlsx/README.md) at source commit
`d111dfa23e40e0a18a956bb2c5c3ee28641239d1`, with a complete file/hash manifest.
The source repository remains unchanged.

Current replacements are the
[execution architecture](../architecture/20260831-v1.0-neatxlsx-streaming-autofit-architecture.md),
[caller migration guide](../how-to-guides/20260831-v1.0-migrate-axiomkit-xlsx.md),
and [benchmark protocol](../benchmarks/20260831-v1.0-xlsx-writer-benchmark-protocol.md).
The archive README maps every imported topic to those destinations and records
the original optimization scope without inventing an undocumented rationale.
This completes documentation coverage for the scoped XLSX source material; it
does not rerun the historical benchmarks, implement delayed widths, or change
the package/release state.
