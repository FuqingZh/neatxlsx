# neatxlsx M0/M1 Report Trust Implementation Plan

Version: v1.0
Date: 2026-08-11
Status: M0 complete; M1 implementation complete locally; release readiness pending

## Authority

This plan implements the selected semantics in the
[M0/M1 report-trust design proposal](../architecture/20260811-v1.0-neatxlsx-m0-m1-report-trust-design-proposal.md).
It is subordinate to the current
[architecture](../architecture/20260728-v1.0-neatxlsx-architecture.md) and
[public API contract](../architecture/20260728-v1.0-neatxlsx-public-api-contract.md)
until each behavior is implemented and the current documents are updated.

The broader priority and milestone order remain in the
[future optimization plan](20260810-v1.0-neatxlsx-future-optimization-implementation-plan.md).

## Delivery outcome

M0 is complete when deterministic reference scenarios, compact manifests,
independent structural oracles, and the visual rubric run from repository
sources without committing generated XLSX binaries.

M1 is complete when every admitted dtype follows the selected storage and
display matrix, unsupported dtypes fail schema preflight, all autofit modes
share one value converter, format precedence is enforced, and the public
contract and release evidence describe the corrected behavior.

The original M0/M1 trust slices added no public symbol or parameter. A later
0.2.0 delivery checkpoint, authorized by a separate public-contract decision,
adds keyword-only `header_row_formats` and `column_formats` without changing
the M1 dtype or transaction semantics.

## Work boundaries

### In scope

- reference cases, manifests, generator, test oracle, and test-plan updates;
- private dtype plans and lazy Polars normalization;
- private Python/PyO3 bridge ABI v3;
- Rust value conversion, warning aggregation, temporal conversion, and
  per-column inferred formats;
- `Format` validation and format-layer correction;
- compatibility, package, CI, documentation, and release gates.

### Out of scope

- M2 visual-default changes and general column-rule APIs beyond the narrow
  `column_formats` Format-patch mapping;
- M3 openpyxl interoperability;
- benchmark-driven M4 optimization;
- generic nested serialization;
- formulas, charts, arbitrary editing, or a new writer backend.

## Baseline to preserve

Before the first implementation slice, record:

- `pdm run check`;
- `git diff --check`;
- current reference probes for Boolean, integer limits, Decimal, temporal,
  categorical, enum, nested, binary, literal-formula, and missing values; and
- current package bridge ABI and contract.

A slice must not alter ZIP64 defaults, sheet splitting, transaction state,
literal-string writes, report offsets, or the number of LazyFrame data sources
used by each autofit mode.

No package is published between partial M1 slices. The release gate runs only
after all M1 acceptance criteria pass.

## Slice 1 — M0 deterministic reference sources

### Changes

1. Add `tests/reference_cases.py` with named factories for:
   `ordinary-scientific`, `mixed-dtype`, `multi-level-header`,
   `multi-sheet-pipeline`, and `split-planning`.
2. Fix all data, column order, temporal units, timezone, decimal scale, sheet
   names, and workbook options in those factories. Do not use random values.
3. Add `scripts/generate_report_reference.py` with:
   - default output under `dist/report-reference/`;
   - scenario selection;
   - `--include-large` for the real Excel-limit artifact;
   - comparison against expected JSON; and
   - `--accept` as the only fixture-replacement path.
4. Add a `report-reference` PDM script.
5. Confirm `dist/` remains ignored.

### Tests

- Unit-test scenario ID uniqueness and deterministic source schemas.
- Run the generator twice and compare canonical JSON.
- Verify normal generation cannot update source fixtures.
- Run lint, format, and typecheck for the new Python and script files.

### Acceptance

- All five scenario definitions are source controlled.
- Four ordinary XLSX artifacts and one compact split-planning artifact can be
  generated from a clean checkout.
- Repeated generation produces identical canonical manifests.
- No XLSX binary is staged.

### Rollback

Remove only the new harness files and PDM script. Runtime code is untouched.

## Slice 2 — M0 structural oracle and visual rubric

### Changes

1. Define manifest schema version `1` and add expected fixtures under
   `tests/fixtures/report-reference/`.
2. Add `tests/integration/test_report_reference.py`:
   - open workbooks with openpyxl using `data_only=False`;
   - canonicalize blank, string, number, boolean, and error cell kinds;
   - inspect selected values and number formats;
   - inspect freezes, merges, dimensions, and selected widths;
   - inspect ZIP/OOXML cell types and literal formula-looking strings; and
   - compare ordered `SheetReport` mappings and warnings.
3. Add synthetic Rust planner tests for shapes immediately below, at, and above
   Excel row and column limits. Assert columns-first then rows ordering and
   half-open source offsets.
4. Record current mixed-dtype deficiencies under `known_gaps`; do not assert
   exact incorrect dtype-description strings.
5. Add the visual rubric and generator commands to the test plan.

### Tests

- `pdm run pytest tests/integration/test_report_reference.py -q`
- focused Rust planner tests;
- one manual generator run;
- `pdm run check`.

### Acceptance

- Each stable invariant is observed through at least two appropriate surfaces
  where practical.
- A manifest mismatch produces a readable field-level diff.
- M1-targeted gaps are visible without being blessed as current contracts.
- The optional large artifact is documented but not required in default CI.

### Rollback

Fixtures and oracle can be revised independently. Preserve the deterministic
scenario factories for later M2 review.

## Slice 3 — private dtype planner and preflight

### Changes

1. Add private dataclasses to `python/neatxlsx/spec.py`:
   - `_ColumnValuePlan`; and
   - `_FormatPlan`, separating role defaults from explicit Workbook role
     patches.
2. Add `python/neatxlsx/_dtype.py`:
   - classify schema entries in source-column order;
   - attach decimal precision/scale and temporal unit/timezone;
   - reject Binary, List, Array, Struct, Object, and unknown opaque dtypes with
     the selected `TypeError`;
   - build lazy String casts for Categorical and Enum; and
   - build fixed-precision ISO 8601 expressions for timezone-aware Datetime.
3. Keep the planner unexported and add a contract assertion that
   `neatxlsx.__all__` is unchanged.
4. In `Workbook.write_sheet()`, invoke schema preflight after
   `collect_schema()` and selector validation but before backend entry.
5. Keep preflight and normalization outside the backend exception block so an
   unsupported dtype does not call `abort()`.
6. Use the normalized schema for Arrow transport while retaining source dtype
   metadata in the ordered plan.

### Required unit matrix

Cover null, Boolean, every signed and unsigned integer family, Int128,
Float32/64, Decimal with several scales, String, Categorical, Enum, Date,
naive and timezone-aware Datetime in ms/us/ns, Time, Duration, and every
rejected family.

For normalized LazyFrames, assert the optimized plan remains lazy and column
order and names do not change.

### Workbook-state test

```python
with Workbook(path) as workbook:
    workbook.write_sheet(valid, "Before")
    with pytest.raises(TypeError):
        workbook.write_sheet(unsupported, "Rejected")
    workbook.write_sheet(valid, "After")
```

After close, only `Before` and `After` exist and both have report entries.

### Acceptance

- Unsupported schemas never enter the native writer.
- Classification is complete and deterministic for the supported Polars range.
- Normalization creates no eager DataFrame collection.
- Public names and signatures are unchanged.

### Rollback

Remove the private planner call and models. No bridge or file-format change has
landed in this slice.

## Slice 4 — bridge v3 and one Arrow conversion path

### Changes

1. Add Rust `ColumnValueKind`, `ColumnValuePlan`, and `WarningCode`
   models in `crates/neatxlsx_core/src/spec.rs`.
2. Extend the private native methods to accept ordered column plans and
   separated format-plan layers.
3. Change both sides together:
   - ABI `2 -> 3`;
   - contract `neatxlsx.xlsx.writer.v2 -> neatxlsx.xlsx.writer.v3`; and
   - transport remains `arrow_c_data`.
4. Update `_native.pyi`, bridge extraction, and installed-package smoke tests.
5. Replace body `AnyValue` conversion with Arrow-array conversion in both
   autofit scanning and write rendering. Keep AnyValue only for custom header
   extraction.
6. Rename internal `CellValue::None` to `Blank` and add
   `CellValue::Boolean(bool)`.
7. Render Boolean with rust_xlsxwriter's native boolean write.
8. Make width estimation handle Boolean and exact text without numeric
   reparsing.

### Equivalence tests

For a primitive table, compare all four autofit modes on:

- openpyxl cell kind and value;
- OOXML `t` attribute;
- warnings; and
- report structure.

The only intended output correction in this slice is native Boolean storage.

### Package tests

- Python v3 plus Rust v3 imports.
- Python v2 plus Rust v3 and Python v3 plus Rust v2 both fail with the bridge
  mismatch diagnostic.
- Wheel and sdist validation import the built extension.

### Acceptance

- There is one body-value converter in the Rust codebase.
- Autofit mode cannot select a different value implementation.
- Boolean cells are native and literal-string safety is unchanged.
- The package cannot load a mismatched private bridge.

### Rollback

Revert Python and Rust ABI changes as one unit. Never leave a mixed bridge
version on the branch.

## Slice 5 — exact integer and Decimal semantics

### Changes

1. Add integer conversion for all admitted Arrow primitive widths:
   - count significant decimal digits without first casting to `f64`;
   - write up to 15 digits as `Number`; and
   - write 16+ digits with `String` from the original integer.
2. Add Decimal32/64/128/256 conversion as supported by the admitted Polars
   Arrow output:
   - retain the unscaled integer and dtype scale;
   - use a numeric cell only when significant digits and scale are both at
     most 15;
   - generate exact fixed-point text otherwise; and
   - preserve scale-derived trailing zeros.
3. Add `[precision-as-text]` warning aggregation keyed by logical source
   column and code.
4. Add inferred Decimal number formats:
   - scale 0: `0`;
   - positive safe scale: `0.` followed by exactly `scale` zeros.
5. Ensure scientific notation never transforms exact-text fallback cells.
6. Make the same conversion result feed body autofit width estimation and
   actual writing.

### Boundary matrix

Test positive and negative values at 14, 15, and 16 digits; zero; Int64 and
UInt64 extrema; Int128 values; leading decimal zeros; Decimal scale 0, 2, 15,
and 16; 15- and 16-digit unscaled values; null; and mixed safe/unsafe cells in
one column.

### Oracle requirements

- openpyxl observes exact values and intended kinds.
- OOXML confirms text fallbacks are strings, never formulas.
- Reading displayed text reconstructs the exact source integer or fixed-point
  decimal.
- Each affected logical column receives exactly one warning, including when it
  spans multiple physical worksheets.

### Acceptance

No integer or Decimal input is silently rounded. Ordinary values remain native
numbers, and unsafe values remain exact literal text.

### Rollback

The converter can be reverted independently before release, but the M0
precision fixtures remain. Do not publish an M1 release with only some integer
widths protected.

## Slice 6 — temporal, categorical, and unsupported dtype activation

### Changes

1. Activate the lazy Categorical and Enum casts and verify exact labels.
2. Activate fixed-precision ISO 8601 text for timezone-aware Datetime.
3. Implement Date, naive Datetime, Time, and Duration conversion from Arrow
   integer units using polars-arrow temporal helpers and rust_xlsxwriter
   date/time support.
4. Centralize:
   - Excel-range checks;
   - millisecond-alignment checks;
   - Excel serial conversion; and
   - integer-millisecond round-trip checks.
5. Implement exact text fallbacks:
   - ISO Date, Datetime, and Time at source-unit precision; and
   - signed raw Duration integer plus `ms`, `us`, or `ns`.
6. Add `[temporal-as-text]` warning aggregation.
7. Attach inferred formats `yyyy-mm-dd`,
   `yyyy-mm-dd hh:mm:ss.000`, `hh:mm:ss.000`, and
   `[h]:mm:ss.000`.
8. Delete the generic Arrow dtype-description fallback. An unknown plan kind is
   an internal error; an unsupported Polars dtype has already failed Python
   preflight.

### Temporal matrix

Test:

- start and end of the selected Excel range;
- one value immediately outside each range boundary;
- midnight, end-of-day, and multi-day Duration;
- positive, zero, and negative Duration;
- millisecond-aligned and sub-millisecond values in ms/us/ns dtypes;
- naive and timezone-aware Datetime, including UTC and a nonzero offset;
- daylight-saving offset examples where supported by Polars;
- null cells; and
- values that cross a physical sheet split.

### Acceptance

- No admitted dtype writes a dtype description.
- Supported native temporal cells round-trip at millisecond precision.
- Every value outside the native contract is exact literal text.
- Timezones are never silently removed.
- Categorical and Enum output contains labels, not dictionary metadata.

### Rollback

Revert a temporal kind only together with its planner admission. Never restore a
generic dtype-text fallback for user values.

## Slice 7 — format validation and precedence

### Changes

1. Add `Format.__post_init__()` with the selected type, range, alignment,
   border, nonempty-string, and RGB validation.
2. Normalize accepted colors to uppercase `#RRGGBB` at the bridge boundary.
3. Change default format construction so body role defaults directly use
   border 0 and the header role directly uses border 1.
4. Remove `_WriteOptions.base_format_patch` from Python, PyO3, and core
   structs.
5. Preserve default role patches and explicit Workbook role patches as separate
   private layers.
6. In `plan_column_formats()`, merge exactly:

   ```text
   role default
   < inferred dtype number format
   < explicit Workbook role override
   < scientific conditional overlay
   ```

7. Propagate the final per-column plans to all physical split sheets.
8. Replace silent Rust parsing fallbacks with unreachable/internal errors;
   invalid public values must have failed in Python.

### Tests

- Every accepted and rejected alignment and vertical-alignment token.
- Border integers 0 and 13 accepted; -1, 14, booleans, and strings rejected.
- Font-size boundaries, booleans, and non-integers.
- Valid colors with and without `#`; invalid lengths and digits.
- `Format.replace()` validation.
- User body borders survive writing.
- Header border remains.
- An inferred Decimal scale remains when the user patch changes only color.
- An explicit user `num_format` replaces the inferred scale.
- The same styles appear on every split part.

### Acceptance

Invalid formats cannot reach Rust; user non-`None` fields are never erased by
a later base patch; and tested precedence matches the design.

### Compatibility note

Some previously ignored invalid inputs now raise immediately. Record this in
the M1 release notes as intentional fail-fast behavior.

### Rollback

The direct body/header defaults and removal of `base_format_patch` must revert
together. Keep the validation tests even if individual accepted aliases are
adjusted during review.

## Slice 8 — M1 convergence, documentation, CI, and release readiness

### Changes

1. Move all fixed M0 `known_gaps` to ordinary target assertions.
2. Add a single integration dtype-contract matrix for DataFrame and LazyFrame
   across all autofit modes.
3. Promote minimum and latest supported Polars contract tests from the optional
   nightly-only surface to a required Python 3.13 CI job. Keep prerelease
   allowed to fail in nightly.
4. Update together:
   - current architecture;
   - public API contract;
   - test plan;
   - README examples where value behavior is visible;
   - `Format` and `SheetReport.warnings` docstrings;
   - type declarations and installed-package contract tests; and
   - release notes for the targeted `0.2.0`.
5. Regenerate M0 evidence and perform the visual rubric in Excel and
   LibreOffice for the ordinary four workbooks.
6. Run the optional real-limit scenario at least once for release evidence.
7. Use `pdm run select-checks --base <sha> --head <sha>` to record affected
   validation lanes.

### Required final gate

```text
pdm run check
pdm run report-reference
pdm run pytest tests/integration/test_dtype_contract.py -q
pdm run pytest tests/integration/test_report_reference.py -q
git diff --check
git status --short
```

In CI, both the minimum and latest Polars lanes must pass the integration and
contract tests. The release build must pass the repository's existing
`build-release` workflow on the exact release commit before publication is
considered.

### Acceptance

- M0 has no remaining gap for an M1-admitted dtype.
- The exact same source values and warnings are observed for DataFrame,
  LazyFrame, and every autofit mode.
- Package metadata, Python, stub, and native bridge agree.
- Current docs describe implemented behavior rather than proposals.
- No package is published and no tag is created without a separate explicit
  release authorization.

### Rollback

If the final gate exposes a semantic conflict, preserve M0 and revert only the
smallest M1 activation slice. A bridge rollback remains paired. Do not weaken
fixtures or delete warnings to make the gate pass.

## Review checkpoints

Reviewers should reject a slice when it:

- adds a public name or parameter without a separate contract decision;
- materializes Python rows or adds a source pass to the ordinary path;
- converts a value to `f64` before deciding whether it is safe;
- writes a dtype description as user data;
- silently removes timezone or sub-millisecond information;
- catches a schema `TypeError` inside the backend-abort block;
- duplicates conversion logic by autofit mode;
- updates an expected manifest using an ordinary test command; or
- claims M1 complete before minimum/latest Polars and package gates pass.
