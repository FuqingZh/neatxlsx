# neatxlsx Test Plan

Version: v1.4
Date: 2026-09-01
Status: current

## Layers

- `tests/unit`: pure normalization, value-object, selector, and property tests.
- `tests/contract`: exact public names, signatures, defaults, reports, and
  exception hierarchy.
- `tests/integration`: Python/PyO3/Rust writes and transactional behavior.
- `tests/package`: installed wheel metadata and import checks.
- Rust unit tests: worksheet planning, conversion, and strategy algorithms.

Tests are small and deterministic so a developer or coding agent can select,
run, and interpret them without an online model judge.

## XLSX oracles

Use three independent views:

1. openpyxl for reader-observed values, styles, freezes, and formula safety;
2. ZIP/OOXML assertions for container versions, required parts, and merges;
3. compact JSON manifests for canonical report structure.

Binary XLSX hashes are not a primary oracle because ZIP metadata and producer
details aren't the contract.

## M0 report-reference harness

The deterministic M0 sources live in `tests/reference_cases.py`. Generate the
four ordinary workbook artifacts and the compact split-planning manifest with:

```text
pdm run report-reference
```

Generated XLSX and actual JSON files are written under the ignored
`dist/report-reference/`. Expected compact manifests live under
`tests/fixtures/report-reference/`. Replacing a fixture is an explicit action:

```text
pdm run python scripts/generate_report_reference.py --accept
```

The default command must compare manifests and fail with a field-level diff
when output changes. `--include-large` adds the optional real row-limit
workbook; it is release evidence rather than a normal pull-request job.

`tests/integration/test_report_reference.py` independently checks the expected
report mappings, dimensions, freezes, merges, selected widths, sentinel cell
kinds/values/formats, and ZIP/OOXML worksheet structure. Formula-looking text
must remain a literal string with no `<f>` element. The split-planning source
is additionally checked by Rust unit tests at the exact Excel row and column
boundaries.

The M1 mixed-dtype manifest now promotes admitted dtype behavior to ordinary
sentinel assertions and has no stale fallback gaps. A future `known_gaps`
entry must describe an intentionally deferred behavior, never bless a dtype
description or lossy value as a current contract.

### Visual rubric

For representative review, record pass, concern, or not-applicable for:

- header hierarchy and merged-header clarity;
- text, numeric, and temporal alignment;
- readable number display and scientific notation;
- missing-value visibility;
- width, wrapping, density, and obvious truncation;
- consistency across sheets and physical split parts; and
- formula-looking text remaining visibly literal.

Visual review is release evidence, not a screenshot or binary-hash pull-request
gate. When a local reader cannot open the default ZIP64 artifact, inspect a
same-source `use_zip64=False` copy and separately retain the ZIP/OOXML and
openpyxl evidence for the default artifact.

## Gates

`pdm run check` is the complete local gate: Ruff, Pyright, Rust format/clippy/
tests, Python tests, package build, and artifact validation. Pull requests run
affected fast lanes; main runs all fast lanes. Nightly adds minimum/latest
Polars, property, ZIP64, and prerelease smoke. Release candidates build each
platform artifact once, validate the bundle, and publish those same bytes.

The release bundle gate requires five CPython 3.11 ABI3 wheels (Linux x86_64
and aarch64, macOS x86_64 and arm64, and Windows AMD64) plus exactly one source
distribution. Every artifact must carry the workspace package version, every
wheel must load the native bridge in its target build environment, the source
distribution must install successfully in a clean bundle job, and `twine check`
must accept the complete bundle. Each target wheel and the clean sdist install
also verify the public `Workbook.write_sheet` signature and the paired private
ABI/contract v6. The immutable manifest records that version, the source
commit, and each artifact hash. TestPyPI and PyPI publishing must consume the
same successful `build-release` bundle rather than rebuilding artifacts.

Large synthetic ZIP64 validation is scheduled/release evidence rather than a
normal pull-request cost. Benchmarks cover tall, wide, LazyFrame, memory, and
output validity; baseline documents are created only after a measured run.
The [benchmark protocol](../benchmarks/20260831-v1.0-xlsx-writer-benchmark-protocol.md)
defines the current scripts' workloads, timer/validation boundaries, and RSS
limitations. Imported axiomkit results remain historical and cannot substitute
for a current baseline.

Per-column format rebasing across physical parts has a small Rust boundary test
in the default gate for both header and body patches. Integration tests cover
generated, one-row, and two-row custom headers; header row/column precedence;
body isolation; selector validation; merged-header recovery; canonical
single-stream propagation across every autofit mode; and both openpyxl and
OOXML style readback. The private canonical batch regression rejects the
merged-header conflict before mutation, then writes the same sheet name and
closes successfully; a post-mutation stream failure poisons the native writer.
The explicit large gate writes 16,385 real columns and
reads back the rebased header styles on both column parts; its row-limit case
verifies repeated header-column patches on every row part:

```text
NEATXLSX_INCLUDE_LARGE=1 pdm run pytest tests/integration/test_format_overrides.py -k pagination -q
```

## Acceptance evidence

Completion requires fresh commands, final wheel inspection, installed-wheel
smoke, and explicit reporting of any platform or large-file check not run
locally.
