# neatxlsx Test Plan

Version: v1.0  
Date: 2026-07-28  
Status: current

## Layers

- `tests/unit`: pure normalization, value-object, selector, and property tests.
- `tests/contract`: exact public names, signatures, defaults, reports, and
  exception hierarchy.
- `tests/integration`: Python/PyO3/Rust writes and transactional behavior.
- `tests/package`: installed wheel metadata and import checks.
- Rust unit tests: worksheet planning, conversion, and strategy algorithms.

Tests are small and deterministic so a developer or coding agent can select,
run, and interpret them without an online model judge.

## XLSX oracles

Use three independent views:

1. openpyxl for reader-observed values, styles, freezes, and formula safety;
2. ZIP/OOXML assertions for container versions, required parts, and merges;
3. compact JSON manifests for canonical report structure.

Binary XLSX hashes are not a primary oracle because ZIP metadata and producer
details aren't the contract.

## Gates

`pdm run check` is the complete local gate: Ruff, Pyright, Rust format/clippy/
tests, Python tests, package build, and artifact validation. Pull requests run
affected fast lanes; main runs all fast lanes. Nightly adds minimum/latest
Polars, property, ZIP64, and prerelease smoke. Release candidates build each
platform artifact once, validate the bundle, and publish those same bytes.

The release bundle gate requires five CPython 3.11 ABI3 wheels (Linux x86_64
and aarch64, macOS x86_64 and arm64, and Windows AMD64) plus exactly one source
distribution. Every artifact must carry the workspace package version, every
wheel must load the native bridge in its target build environment, the source
distribution must install successfully in a clean bundle job, and `twine check`
must accept the complete bundle. The immutable manifest records that version,
the source commit, and each artifact hash. TestPyPI and PyPI publishing must
consume the same successful `build-release` bundle rather than rebuilding
artifacts.

Large synthetic ZIP64 validation is scheduled/release evidence rather than a
normal pull-request cost. Benchmarks cover tall, wide, LazyFrame, memory, and
output validity; baseline documents are created only after a measured run.

## Acceptance evidence

Completion requires fresh commands, final wheel inspection, installed-wheel
smoke, and explicit reporting of any platform or large-file check not run
locally.
