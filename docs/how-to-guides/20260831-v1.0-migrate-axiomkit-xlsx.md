# Migrate an axiomkit XLSX caller to neatxlsx

Version: v1.0
Date: 2026-08-31
Status: current caller guide; not a compatibility-alias promise

## Scope

Use this guide to migrate an XLSX report-table caller. neatxlsx is independent
of axiomkit; neither package redirects to the other. The
[old axiomkit v2 rename note](../archive/axiomkit-xlsx/docs/migration/xlsx_writer_v2.md)
is historical and is not the neatxlsx API. This guide uses the current
[public contract](../architecture/20260728-v1.0-neatxlsx-public-api-contract.md).

Install a neatxlsx wheel for a supported platform. Python 3.11+ and
Polars 1.38.1+ are required. For source development, follow the repository's
`pdm sync -G dev` and `pdm run develop` instructions; a source checkout alone
does not build the private native extension.

## Replace the public entrypoint and policy objects

| axiomkit concept | neatxlsx replacement | Migration detail |
| --- | --- | --- |
| `axiomkit.io.XlsxWriter` | `neatxlsx.Workbook` | No old-name alias; use a context manager or explicit `close()` |
| `CellFormatPatch` (older `CellFormatSpec`) | `Format` | Pass role formats to `Workbook`; explicit body/header patches use the current `write_sheet` arguments |
| `AutofitPolicy` (older `AutofitCellsPolicySpec`) | `Autofit` | Use `mode`, `max_rows`, `min_width`, `max_width`, `padding` |
| `ScientificPolicy` | `ScientificNotation` | Use `scope`, `min_absolute`, `max_absolute`; default scope is `none` |
| `XlsxWriteOptions`, `XlsxValuePolicy`, `XlsxRowChunkPolicy` | `Workbook` keyword arguments | Map each setting explicitly; do not pass the old `options_write` object |
| `SheetSlice` / native report objects | `SheetReport`, `WorksheetPart` from `report()` | Source offsets use half-open intervals; physical names are resolved by the writer |
| Old bridge ABI/contract | Private paired neatxlsx extension | Do not import or reuse axiomkit's native extension |

Common argument migrations:

| Old argument/field | Current argument/field |
| --- | --- |
| `write_sheet(body=...)` | `write_sheet(data=...)` (positional input is also accepted) |
| `fmt_text`, `fmt_integer`, `fmt_decimal`, `fmt_scientific`, `fmt_header` | `Workbook(text_format=..., integer_format=..., decimal_format=..., scientific_format=..., header_format=...)` |
| `should_use_zip64` inside write options | `Workbook(use_zip64=...)` |
| `should_keep_missing_values` | `keep_missing_values` on `Workbook` or `write_sheet` |
| `should_infer_numeric_cols`, `should_infer_integer_cols` | `infer_numeric_columns`, `infer_integer_columns` |
| Value policy `missing_value_str`, `nan_str`, `posinf_str`, `neginf_str` | `Workbook(missing_value=..., nan_value=..., positive_infinity=..., negative_infinity=...)` |
| Value policy `integer_coerce` | `Workbook(integer_coerce=...)` |
| Row chunk `fixed_size` | `Workbook(chunk_size=...)` |
| `cols_integer`, `cols_decimal` | `integer_columns`, `decimal_columns` |
| `num_frozen_cols`, `num_frozen_rows` | `freeze_columns`, `freeze_rows` |
| `should_merge_header` | `merge_header` |
| `policy_autofit` | `autofit` |
| Autofit `height_body_inferred_max`, `width_cell_min`, `width_cell_max`, `width_cell_padding` | `Autofit(max_rows=..., min_width=..., max_width=..., padding=...)` |
| `policy_scientific` | `scientific_notation` |
| Scientific `thr_min`, `thr_max` | `ScientificNotation(min_absolute=..., max_absolute=...)` |

These are concept mappings, not permission to unpack old configuration objects
into new constructors. Enum-like format fields use the values accepted by
`Format`; old Rust planning and merge helper types are not top-level exports.
Numeric and integer inference default to enabled. Explicit column selections
override inferred roles on those columns while inference continues elsewhere.
The old `cols_decimal=False` sentinel is not accepted: omit `decimal_columns`
when no explicit selection is intended, and configure `infer_numeric_columns`
and `infer_integer_columns` separately if automatic roles are unwanted. Bool
and empty-sequence column selections are rejected. The removed scientific
`height_body_inferred_max` option has no replacement; scientific formatting is
decided per cell, whereas `Autofit.max_rows` controls width estimation only.
Custom adaptive chunk-policy thresholds are not public neatxlsx parameters;
retain automatic chunking or select a fixed `chunk_size` explicitly.

## Write and verify a migrated report

```python
import neatxlsx as nx
import polars as pl

data = pl.DataFrame({"Sample": ["A", "B"], "Count": [12, 18], "Score": [0.125, 0.375]})

with nx.Workbook(
    "report.xlsx",
    header_format=nx.Format(bg_color="#D9EAF7"),
    decimal_format=nx.Format(num_format="0.000"),
    use_zip64=True,
) as workbook:
    workbook.write_sheet(
        data,
        "Results",
        integer_columns="Count",
        decimal_columns="Score",
        freeze_columns=1,
        autofit=nx.Autofit(mode="all", max_rows=20_000),
        scientific_notation=nx.ScientificNotation(scope="none"),
    )
    report = workbook.report()

assert report[0].worksheets[0].row_stop == data.height
```

The target parent directory must already exist. Native generation failure
aborts the workbook; normal context exit saves and replaces the target.
Replacement failure raises `CommitError`: retain the workbook object to retry
`close()`, or call `abort()` to discard the prepared temporary output.

Check representative values and number formats with an independent reader,
including nulls, formula-looking strings, precision-sensitive numbers, and
temporals. Current neatxlsx intentionally has dtype admission, exact-text
fallbacks, and warnings that differ from older axiomkit behavior. Unsupported
nested/binary/object dtypes fail schema preflight. Do not assume the original
extraction's behavior equivalence extends to every subsequent release.

## ZIP64 and reader compatibility

ZIP64 remains enabled by default. It permits ZIP entries/container metadata
beyond classic ZIP size limits; the relevant uncompressed XML size is not the
same as the final compressed `.xlsx` size. Even a small default workbook may
require a ZIP64-capable reader. ZIP64 does not raise Excel's worksheet row or
column limits, and opting out does not enable formula interpretation.

If a downstream reader specifically requires classic ZIP, use:

```python
import neatxlsx as nx
import polars as pl

with nx.Workbook("legacy-reader.xlsx", use_zip64=False) as workbook:
    workbook.write_sheet(pl.DataFrame({"value": [1, 2]}), "Data")
```

Keep that opt-out limited to outputs known to fit classic ZIP constraints and
validate with the actual downstream reader. An oversized classic-ZIP export
can fail during finalization. There is no automatic ZIP64 mode or a guarantee
that output compression alone keeps classic ZIP safe. See the
[container/transaction architecture](../architecture/20260728-v1.0-neatxlsx-architecture.md).

## Streaming and autofit

All autofit modes consume one LazyFrame batch stream. For `body/all`, body
widths are measured online while rows are written and applied after the stream
is exhausted. `all` includes both header and body estimates, while `max_rows`
controls how much of the body is measured. Use `max_rows=None` only when
full-body estimation is intended. Neither mode promises exact Excel font-layout
measurement.
See the [execution architecture](../architecture/20260831-v1.0-neatxlsx-streaming-autofit-architecture.md)
before changing input evaluation or relying on physical split names/order.
