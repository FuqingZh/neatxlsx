# neatxlsx 0.2.0 release notes

Release date: 2026-08-24

The M1 report-trust implementation keeps the public Python names and preserves
all existing `Workbook.write_sheet()` calls while correcting cell semantics
and adding three keyword-only format controls:

## Public API and formatting

- `header_row_formats` assigns a `Format` patch to each custom header row, with
  `None` inheriting the workbook header format;
- `header_column_formats` maps one logical data-column name or zero-based index
  to a generated/custom-header patch, after the workbook header and row patch;
  nonempty mappings are rejected with `merge_header=True`;
- `column_formats` maps one column name or zero-based index to a body-cell
  `Format` patch, using precedence default role, inferred dtype role, workbook
  role format, then column rule;
- all three controls are validated before native backend entry and propagate
  across every physical split worksheet; header-column and body-column patches
  remain distinct and are independently rebased on column pagination;
- the native direct, buffered, and single-pass entrypoints repeat the merged
  header compatibility preflight before worksheet creation, preserving writer
  usability and sheet-name availability after rejection.

## Cell semantics

- booleans are written as native Excel boolean cells;
- ordinary integers and decimals remain numeric, while values beyond Excel's
  safe precision are exact literal text with one `[precision-as-text]` warning
  per affected logical column;
- dates, naive datetimes, times, and safe durations use inferred Excel number
  formats, with exact text fallbacks and `[temporal-as-text]` warnings;
- categorical and Enum columns are lazily normalized to labels;
- unsupported nested or opaque dtypes fail schema preflight without poisoning
  an open workbook;
- `Format` validates domains and normalizes RGB colors; and
- the private Arrow bridge is paired at ABI/contract v5.

## Compatibility and artifacts

The release preserves Python 3.11+ support and ships CPython 3.11 ABI3 wheels
for Linux x86_64/aarch64, macOS x86_64/arm64, and Windows AMD64, plus one source
distribution. Existing 0.1.0 call signatures remain accepted when the three
additive keyword-only format arguments are omitted. Inputs that were previously
accepted but had invalid `Format` domains or unsupported nested/opaque dtypes
now fail early instead of being ignored or rendered as dtype descriptions.

## Release validation

Release validation uses:

```text
CARGO_BUILD_JOBS=1 pdm run check
NEATXLSX_INCLUDE_LARGE=1 pdm run pytest tests/integration/test_format_overrides.py -k pagination -q
```

The exact release commit must also pass current-head CI/review and the
`build-release` workflow. That workflow builds five wheels and one sdist once,
checks their version, contents, public signature, native ABI/contract v5,
installation, and hashes, and writes an immutable manifest. PyPI publication
and the GitHub release consume those same bytes without rebuilding them.
