# neatxlsx 0.2.1 release notes

Status: published on 2026-09-08.

## Streaming and column widths

- All autofit modes consume one Arrow input stream through the Python API.
  Body/all no longer replay the LazyFrame to plan widths before writing.
- Column widths accumulate online and are applied during finalization across
  physical worksheets. Logical sampling limits and split mappings are retained.
- Numeric width estimation uses the selected Excel number format through
  cached `ssfmt` parsing, with the upstream text-width metric and a bounded
  East Asian adjustment. Unsupported formats retain the documented fallback.
- Public signatures, Python 3.11+ support, literal-string writes, report
  mappings, and transactional output replacement are retained. The private
  Python/native pair advances to ABI v6 and uses Arrow C Data transport.

Concrete column widths may change after upgrading. Width estimates are not a
full Excel font/locale renderer, and merged-header width allocation remains
unchanged. General end-to-end speedup is not promised: writing and compression
still contribute costs, and display-aware estimation can add work. Recorded
performance costs were explicitly accepted for this release.

## Validation

Local functional, static, packaging and real Excel-limit checks passed.
Versioned candidate CI, minimum/latest Polars compatibility, and five-platform
wheel/sdist validation passed. The user confirmed normal open/display/edit/
save-reopen behavior in desktop Excel 16.0.20326.20132. PyPI and GitHub assets
were checked against the immutable build manifest after publication.
