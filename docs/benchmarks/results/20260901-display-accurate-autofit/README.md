# Display-accurate single-pass autofit evidence

Date: 2026-09-01
Status: implementation and local evidence recorded; **not accepted for release**

This directory is a compact, reproducible evidence record for the display-accurate
estimator and its narrow measured East Asian fallback. The contained XLSX, PDF,
and PNG files are deliberate canary evidence, not golden test fixtures and not a
portable font-layout claim.

## Performance verdict

The predeclared `display-autofit` gate has one passing scenario out of six and
therefore **fails overall**. Candidate-to-baseline total-wall ratios from the
clean1 run are:

clean1 was generated by the pre-fix harness: its process exited zero despite
the frozen failing verdicts. The current harness now exits one for an
acceptance-eligible failed, inconclusive, or rejected required verdict. No
rerun is required to establish this mechanical correction because the frozen
workers, native binaries, raw records, and analysis are unchanged.

The retained profiles show no single dominant hotspot. The measured East Asian
helper accounts for 0.35% self time, which is insufficient evidence to justify
candidate-specific fast-path churn. `ssfmt` has no buffer-reuse API at this
integration point, and Excel `General` display semantics cannot be replaced
with the former legacy estimate without changing the accuracy contract. The
profile supports recording the failure; it does not authorize a new
optimization direction.

## Layout

- `performance/clean1/`: frozen plan, raw interleaved samples, analysis, and
  rendered comparison.
- `performance/`: baseline/candidate build provenance.
- `profile/`: bounded full-scan profile configuration, JSON results, and
  readable `perf` reports. Raw `perf.data` and approximately 21 MB generated
  workbooks are intentionally excluded.
- `package-validation.txt`: local sdist, wheel-from-sdist, validation, size,
  and hash record. The binary artifacts themselves are excluded.
- `libreoffice/`: source scripts, generation metadata, default/non-ZIP64 and
  round-trip workbooks, PDF/bbox output, and seven rendered pages. Relative
  paths are preserved for local inspection.

`checksums.txt` contains sorted SHA-256 checksums for every retained evidence
file except itself.
